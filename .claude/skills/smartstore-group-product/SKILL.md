# 스마트스토어 그룹상품 관리

2026-08-23 실사 조사(CDP 라이브 확인) 결과. 그룹상품 = "색상/사이즈처럼
옵션만 다른 여러 상품을 하나의 검색결과로 묶어 노출"시키는 기능 —
일반 상품등록의 "옵션" 기능과 달리, **각 옵션이 독립된 상품(고유
상품번호)으로 등록되고 동일 그룹번호로 그룹핑**되는 구조.

## 기존 구현 (재사용할 것)

`scripts/naver/smartstore/product/models.py::GroupProductData` —
그룹상품 등록용 표준 데이터 모델(dataclass). 필드: name, category,
model_name, brand, manufacturer, self_made, vat_type, product_status,
minor_purchase, sale_period, kc_exemption, certification, gift,
event_text, main_image, additional_images, image_mode, description.
가격/재고 필드가 없다 — **그룹상품 자체엔 가격·재고가 없고, 그룹에 속한
개별 상품(옵션)마다 별도로 설정**하는 구조이기 때문(등록 화면 안내문 그대로).

`GeneralProductRegister`에 대응하는 **`scripts/naver/smartstore/group_product_register.py::GroupProductRegister`**
(raw CDP 기반, 2026-08-23 신규)가 카테고리~옵션속성 입력까지 구현돼 있다.

**핵심 발견**: 그룹상품 등록 화면은 일반 상품등록(React)과 달리 **AngularJS +
selectize.js**로 만들어져 있다 — 같은 스마트스토어센터 안에서도 화면마다
프레임워크가 다르다. 판매옵션 입력창은 selectize가 만든 가짜 UI이고, 실제
값은 화면에 안 보이는 `<select multiple>`에 selectize 내부 API로만
반영된다. `input.value` 네이티브 setter로 텍스트만 주입하면 화면엔 보여도
"목록으로 적용" 버튼이 계속 비활성 상태로 남는다 — 반드시
`$(select)[0].selectize.createItem(값)` + `angular…$rootScope.$apply()`
순서로 채워야 한다(자세한 코드는 해당 파일 docstring 참고).

**미해결 함정**: 카테고리 트리 리프 클릭이 페이지 새로고침 직후 반복
실행하면 포커스만 잡히고 실제 선택으로 안 이어지는 경우가 있다(원인 미상,
`GroupProductRegister.is_category_applied()`로 반드시 성공 확인 필요).
남은 작업(일괄입력 그리드/이미지/저장)은 이 스킬 5번 섹션 참고해 신규 개발.

## 좌측 메뉴 구조 (상품관리 > 그룹상품 관리)

```
그룹상품 관리
├── 그룹상품 소개       #/products/standard-group-product/intro
├── 그룹상품 등록       #/products/standard-group-product/create
├── 그룹상품 조회/수정   #/products/standard-group-product-list
├── 그룹상품 리뷰이동    #/review-movement/search
└── 그룹상품 노출 관리   #/display/group-product-exposure
```

## 화면별 조사 결과

### 1. 그룹상품 소개
기능 홍보 페이지. 처리할 데이터 없음. "검색 노출 기회를 높인다", "옵션이
복잡한 상품을 단위당 가격 비교해서 보여준다" 등 그룹상품의 가치 설명.

### 2. 그룹상품 등록 (`create`)
- 상단 탭: "상품 등록" / "그룹상품 등록"(현재 화면, Beta 배지)
- **카테고리 선택 필수** — 카테고리명 검색/선택/템플릿 3가지 입력 방식,
  "최종 카테고리까지 선택해야" 저장 가능
- 등록 방식: "기존에 상품의 옵션을 등록하는 것처럼 카테고리별 판매옵션
  가이드에 따라 판매옵션 정보를 설정" → 각 판매옵션이 옵션 없는 단일상품
  으로 등록되며, 동일 그룹번호로 그룹핑됨
- **일부 정보는 그룹 단위 공통 정보로만 등록 가능** — 등록 후 수정하려면
  "그룹상품 수정"에서만 가능(개별 상품 수정에서는 불가)
- 하단 버튼: 저장하기 / 취소, "동영상 가이드 열기"

### 3. 그룹상품 조회/수정 (`standard-group-product-list`)
등록된 그룹상품을 상태별로 조회/수정. 상단 카운트 배지 6종: 대기/판매중/
품절/판매중지/판매종료/판매금지(전부 0건, 2026-08-23 기준 — 아직 그룹상품
없음). 필터: 채널(전체/스마트스토어/쇼핑윈도), 기간(그룹상품등록일 기준
오늘~전체, 1년까지 프리셋), 카테고리, 상세검색.

**참고**: 이 카운트는 `tools/runtime/cdp_click_watch.py`의
`COUNT_LABELS`에 아직 등록 안 됨 — 라벨이 일반 상품관리(41건/7건/34건)와
같은 CSS 의사요소 렌더링 방식이라면 동일하게 추출 불가할 가능성 높음
(미검증, 그룹상품이 실제로 있을 때 재확인 필요).

### 4. 그룹상품 리뷰이동 (`review-movement/search`)
개별 상품으로 달린 리뷰를 그룹상품(대표 상품)으로 재배치하는 기능.
"리뷰의 상품/옵션정보와 일치하지 않는 상품으로 리뷰를 이동하면 표시광고법
등 관련 법령 위반"이라는 경고 문구 있음 — **함부로 자동화하면 안 됨**
(리뷰-상품 매칭 정확성 검증 없이는 사용 금지).
- "리뷰이동 요청하기" 버튼으로 새 요청 생성
- 검색조건: 리뷰 보낼 그룹상품번호 / 리뷰 보낼·받을 상품번호 / 요청ID
- 목록: 요청ID, 그룹상품번호/명, 진행상태, 이동한 리뷰수, 최근 리뷰이동일

### 5. 그룹상품 노출 관리 (`display/group-product-exposure`)
스토어 내 상품목록에서 그룹상품 노출 방식을 커스터마이즈.
- 기본 동작: 그룹상품은 중복제거 후 "대표상품" 1개만 노출(대표상품은
  구매자의 필터/정렬/키워드 검색 조건에 따라 유동적으로 바뀜, **임의
  지정 불가**)
- 이 페이지에 **개별 등록한 그룹상품**은 중복제거 없이 그룹 내 모든
  전시중 상품이 목록에 노출됨(예외 설정)
- 적용 범위: 스토어 내(전체상품/카테고리 지면)만. 네이버플러스스토어/
  쇼핑검색에는 미적용
- "그룹상품 추가" / "선택삭제" 버튼으로 관리, 목록은 페이지당 10/20/50개

## 다음에 할 일 (미착수)

- 실제 그룹상품이 하나라도 등록된 후 "조회/수정" 화면 카운트 배지의
  innerText 추출 가능 여부 재확인 (일반상품관리처럼 CSS 렌더링일 수 있음)
- 그룹상품 등록 자동화(`GroupProductRegister`)가 필요해지면 카테고리
  선택 → 판매옵션 그리드 입력 → 저장 흐름을 `GeneralProductRegister`
  패턴을 참고해 신규 개발 (기준서 먼저 작성)
