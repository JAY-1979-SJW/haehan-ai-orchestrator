# 네이버 블로그 발행 스킬

기준서: `docs/specs/naver_blog_content_standard.md` (이 스킬의 모든 규칙의 근거 —
불일치가 생기면 기준서를 최신으로 보고 이 스킬을 맞춘다).

## 이 스킬이 하는 일

1. **주제 선정** — `data/blog_topic_research_latest.json`(카페 빈도 + 네이버
   검색광고 실검색량 + 지식iN 실제 질문 3중 검증) 우선 사용. 30일 넘게
   오래됐거나 없으면 먼저 `python scripts/naver/blog/cli/research_blog_topics.py` 실행해
   갱신. AI가 주제를 지어내지 않는다.
2. **중복 방지** — `data/blog_topic_cache.json`의 `posted[].topic` 과 반드시
   대조해서 이미 쓴 주제는 건너뛴다 (2026-08-17 중복 발행 사고 재발 방지).
   ⚠️ 이 파일엔 **AI 자동 발행분만** 들어있다. 사용자가 직접 쓴 글까지
   보려면 `data/blog_posts_cache.json`(전체 103편, [[blog-post-cache-analysis]]
   스킬로 갱신)을 같이 대조한다.
3. **본문 생성** — ⚠️ **`generate_post()`는 쓸 수 없다.** 내부적으로 GPT를
   호출하는데 2026-08-19 사업자 결정으로 차단돼 있어 `OpenAIDisabledError`가
   난다(2026-08-23 실측 확인). **Claude Code가 직접 조사해서 쓰고**
   `blog_publish_manual.py`로 발행한다(아래 '글 작성 원칙' 참조).
   구조는 `[핵심 답변]`→`[기]`→`[승]`→`[전]`→`[결]`→`[CTA]`.
   **제목의 "AI" 필수 규칙은 2026-08-23 폐기됐다** (코드의 강제 부착
   로직도 제거). 제목은 **검색어 우선** — 검색자가 실제 입력할 키워드를
   앞쪽에 배치한다. 내용상 자연스러우면 AI를 넣어도 되지만 강제는 아니다.
4. **이미지** — 기본은 `images.py`(Unsplash). 글 내용에 정확히 맞는 장면이
   필요하면 [[blog-gpt-images]] 스킬(ChatGPT 웹 CDP 생성) 사용.
   `blog_publish_manual.py --check` 단계에서 이미지가 자동 확보돼 원고에
   저장되므로, 승인 검토 시 이미지까지 포함된 상태로 볼 수 있다.
5. **발행/수정** — `publish.py::publish_one()`(신규) 또는 `edit_one()`(기존
   글 수정, log_no 유지). 계정은 `TARGET_BLOG_ID`(현재 `skyjwsin`) 고정.

## 실행 방법

### 신규 N개 발행
```bash
python scripts/naver/blog/cli/blog_ai_batch_20.py --count N
```
`--dry-run` 으로 먼저 시뮬레이션 가능(실제 발행 없이 주제/제목/SEO만 확인).

### 기존 글 수정 (예: 콘텐츠 기준이 바뀌어 재작성 필요할 때)
Python 인라인으로 진행 (`publish.py`의 `connect_and_ensure_login()` +
`edit_one()` 조합) — 아래 "코드 작성 전 확인" 참고. 정형화된 CLI는 아직
없음, 필요 빈도가 늘면 `scripts/naver/blog/cli/blog_edit_existing.py` 로 승격 고려.

### 성과 분석 (유입경로/조회수 순위/방문 추이)
```bash
python scripts/naver/blog/cli/blog_analytics_report.py
```
`BlogAnalytics.full_report()` — 어떤 글/키워드가 실제로 유입을 만드는지
확인해서 다음 배치의 주제 우선순위에 반영.

## 코드 작성 전 확인 (매번)

1. `python tools/hooks/capability_check.py naver blog` 로 기존 구현 재확인
   — 이미 `scripts/naver/blog/marketing/`, `scripts/naver/blog/core/writer.py`
   에 전부 있음. **새로 만들지 말고 이걸 import해서 쓴다.**
2. 프롬프트/구조를 바꿀 거면: `python -m ruff check --config configs/ruff.toml

   `generate_post()` 직접 호출해 `seo['ai_ratio']`·본문 길이·실제 텍스트
   확인 → 라이브 발행/수정 1건만 먼저 → `blog.naver.com/skyjwsin/{log_no}`
   실제로 열어 확인 → 이상 없으면 나머지 배치.
3. 배치 발행/수정은 매번 사용자 승인 후 진행 (외부 공개 발행 = 매번 재확인
   원칙, CLAUDE.md). 이미 승인된 배치 흐름 내부의 sub-step까지 재확인하지
   않음.

## 알려진 함정 (재발 방지)

- **AI 콘텐츠 없이 발행된 사고(2026-08-17)**: 프롬프트가 약하면 모델이
  "규정 설명"으로 되돌아간다 — 반드시 `ai_ratio` 경고를 확인.
- **`_ai_section_ratio()` 계산 버그**: `##`.startswith 체크가 `###` 소제목도
  섹션 경계로 잘못 인식해 비율이 1%대로 오탐된 적 있음 — 현재는 `^##\s`
  (H2만) 로 수정됨. 이 로직 건드릴 때 재확인.
- **동일 주제 중복 발행**: `is_duplicate()` 체크에도 불구 발생한 적 있음 —
  배치 실행 직전 `blog_topic_cache.json` 최신 상태 재확인.
- **로그인 계정 오판**: 닉네임 비교 금지, `admin.blog.naver.com/{blogId}/`
  링크의 실제 blogId로만 판별 (`connect_and_ensure_login()`에 구현됨).
- **전화번호는 노출한다 (2026-08-22 정책 전환, 08-23 재확인)** — 기존
  "전화번호 금지"(08-17)를 뒤집었다. CTA에 `010-7387-6635`를 명시한다.
  **단 순서가 중요하다**: 실측 수치로 "우리가 이 문제를 이렇게 푼다"를
  먼저 증명하고, 번호는 그 다음 마지막 줄. 증명 없이 번호부터 내미는
  CTA는 기준서 위반이다. **유튜브 링크는 2026-08-20부터 허용**(아래 참조).
- **브랜드 표기는 "해한 AI"** — "해한 AI 엔지니어링"(정식 상호)은 이
  블로그에 쓰지 않는다(2026-08-23).

## ⚠️ 2026-08-19 방향 전환 (중요)

경쟁 블로그(EXCELLER77 등 상위 노출 글)와 실제 비교한 뒤 세 가지를 고쳤다.

### ① 마크다운 소제목 금지 → 대괄호
네이버는 마크다운을 렌더링하지 않는다. `## 도입부`가 독자 화면에 **그대로
보이고 있었다**(131개 글 전체). 이제 `[핵심 답변]` 형식으로 쓴다.
`seo_check()`가 `##` 잔존 시 경고한다.

### ② AI 섹션 비중 60~70% → 20~25%
기존 규칙이 "본문의 70% 이상을 AI 자동화 설명에 할애"였는데, 이게 독이었다.
「하도급지킴이 어떻게 쓰나」 검색한 사람은 AI 얘기를 들으러 온 게 아니다.
정작 검색자가 원하는 답이 10%뿐이라 이탈률이 높아지는 구조였다.
네이버 D.I.A.는 "검색자 상황을 얼마나 구체적으로 해결하는가"를 본다.
→ **핵심 답변이 본체(55~65%)**, AI는 뒤에 짧게.

> **현재 유효 규칙(2026-08-20 보완)**: 위 20~25%는 일률 적용이 아니다.
> **주제에 따라 다르다** — 일위대가·물량산출·내역서처럼 제품이 실제로
> 하는 일이면 **40~50%도 정상**(설명이지 광고가 아님). 행정신고성 주제는
> 20% 이하. `seo_check`가 35% 초과 시 경고하지만 **제품 직결 주제면
> 무시해도 된다.**

### ③ 미검증 수치 경고 (`_risky_claims`)
비율을 바꾸자 이번엔 AI가 "2022년 건설산업기본법", "총 공사비의 20~30%",
"최저임금 10,000원" 같은 **없는 수치를 지어냈다**. 틀린 수치는 마크다운
노출보다 신뢰 손상이 크다. 요율·금액·법령연도·조항을 탐지해 발행 전 경고한다.
**경고가 뜨면 사람이 반드시 확인**하고, 확실하지 않으면 숫자를 빼는 게 낫다.

### 상위 블로그가 하는 것 (벤치마킹 대상)
- 구체적 수치: "산재보험료 3.56%", "건강보험료 3.595%", "간접노무비 최대 15%"
- 실무 팁: "주무관님과 협의해 요율을 낮출 수 있는 항목"
- 최신성 명시: "2026.01.01자 변경 제비율표"
- **시리즈 구성 + 공지 고정 + 내부링크** (체류시간·C-Rank에 유리) ← 아직 미적용

### 주제 범위 — 섞지 말 것
C-Rank는 한 주제를 꾸준히 다루는 블로그에 높은 점수를 준다. 이 블로그는
**건설 공무(B2B)** 전용이다. 조명 인테리어(B2C)는 인스타 + `haehan-ai.kr/lighting`
으로 분리한다([[instagram-marketing]] 스킬). 같은 블로그에 섞으면 둘 다 손해다.

## ✍️ 글 작성 원칙 (2026-08-19 사업자 지시 — 이제 Claude Code가 직접 쓴다)

GPT 자동생성은 차단됐다([[openai_guard]]). 글은 **내가 조사해서 직접 쓰고**
`scripts/naver/blog/cli/blog_publish_manual.py` 로 발행한다.

### 1. 기승전결이 명확해야 한다 (2026-08-23: [핵심 답변] 선요약 추가)
```
[핵심 답변]              ← 맨 앞. 2~3문장으로 결론부터. 네이버 AI 검색요약
                            대응 — 스크롤 안 해도 답이 보여야 한다.
[기] 이런 상황이시죠     독자가 막힌 지점을 콕 집어 공감. 질문 반복 금지.
[승] 왜 헷갈리나         쟁점이 무엇인지. 어디서 갈리는지.
[전] 이렇게 하시면 됩니다  ← 본체(50~60%). 순서·서식·판단기준을 구체적으로.
[결] 정리하면            답을 못박는다. 이 문단만 봐도 뭘 할지 알아야 한다.
[CTA]                    ← 주제에 맞게 매번 새로 쓴다(표준문구 복붙 금지)
```
**결론 없이 끝나면 실패한 글이다.** "확인이 필요합니다"로 도망가지 않는다.
`[핵심 답변]`과 `[정리하면]`은 내용이 겹치는 게 정상이다(검색 스캔용 vs
완독 후 확인용) — 단 문장을 그대로 복붙하지 말고 표현을 달리 쓴다.

### 1-1. 분량·태그 기준 (2026-08-23 실측 근거로 대폭 상향)
같은 주제 검색 1~2위 경쟁 글을 직접 열어보니 **5,409자/태그 30개**,
**3,061자/태그 18개**였다(우리 초안은 1,805자/태그 8개였음).

| | 최소 | 목표 |
|---|---|---|
| 본문 | 2,500자 (`MIN_BODY_CHARS`) | 3,500자 (`TARGET_BODY_CHARS`) |
| 태그 | 15개 (`MIN_TAG_COUNT`) | 25개 (`TARGET_TAG_COUNT`) |

태그는 법령명·기관명·핵심개념·업종명·유의어를 최대한 뽑아 채운다. 단
무관한 인기검색어를 끼워넣는 건 금지 — 여전히 "관련어"여야 한다.
분량도 일반론으로 채우지 말고 **정보 밀도를 유지한 채** 늘린다.

### 2. 읽기 편하고 친화적으로
- **짧은 문장.** 한 문장에 한 가지만. 만연체 금지.
- **문단은 2~3줄.** 모바일에서 벽처럼 보이면 바로 나간다.
- **대화하듯이.** "~합니다" 기본, 가끔 "~예요"로 힘 빼기.
  딱딱한 문어체("~함", "~할 것") 금지.
- **전문용어는 풀어서.** "제비율" → "제비율(간접공사비 요율)"처럼 첫 등장에 설명.
- **숫자·목록을 적극 활용.** 줄글보다 눈에 들어온다.
- 어려운 내용일수록 쉬운 말로. 아는 척하는 글이 아니라 도와주는 글.

### 3. 쓰지 말아야 할 것
- 정보가 0인 문장: "복잡할 수 있습니다", "중요합니다", "정확한 이해가 필요합니다"
- **지어낸 수치·법령.** 요율·금액·조항·연도는 검색으로 확인한 것만 쓴다.
  모르면 숫자를 빼고 "어디서 확인하는지"를 알려준다.
- AI 티 나는 문장. 실무자가 쓴 것처럼 자연스럽게.

### 4. 발행 전 반드시
`--check` 로 점검한다. seo_check 가 마크다운 잔존·결론 누락·일반론·
미검증 수치를 잡아준다. 경고가 뜨면 고치고 발행한다.

## 🎯 블로그 목적 (2026-08-20 확정)

**AI 적산·물량산출·내역서 자동화 프로그램 영업.**
콘텐츠는 이 목적에 복무해야 한다. 이걸 놓치면 방향이 두 갈래로 잘못 샌다.

### 잘못된 방향 ① — AI 얘기만 하기 (~2026-08-19까지)
본문 70%를 "AI가 자동화합니다"로 채웠다. 검색자는 답을 못 얻고 이탈했다.
**유입 자체가 안 생긴다.**

### 잘못된 방향 ② — 실무 답변만 하기
답은 잘 주지만 제품 얘기가 없으면 "고맙다" 하고 나간다. **전환이 안 된다.**

### 올바른 방향 — 답을 주고, 그 문제를 실제로 푸는 걸 보여준다
```
[기][승][전][결]  실무 답변으로 신뢰 확보 (본체)
      ↓
```
