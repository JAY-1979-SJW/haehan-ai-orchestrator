## 2. 메일에서 하는 일 (AI 창에 이렇게 시킨다)
| 지시 예 | AI 가 하는 일 | 보내기 |
|---|---|---|
| "새 메일 확인하고 중요한 것만 알려줘" | `mailbox.new` 로 새 메일 헤더 → 제목·보낸 사람으로 읽을 메일만 골라 `mailbox.read` → 분류·요약 | 없음 |
| "9월 이후 '견적' 들어간 메일 모아서 표로 정리" | `mailbox.list`(날짜·검색어·폴더) → 필요한 것만 본문 읽기 → 정리 | 없음 |
| "이 메일에 답장 초안 써줘" (메일을 열어 둔 상태) | 열린 메일(폴더·번호)을 지침에 함께 전달 → 본문 읽기 → 답장 초안 | **초안만** → 승인 카드 |
| "김대리에게 어제 받은 도면 첨부 전달" | 원본 첨부 참조로 전달 초안 | 초안만 → 승인 카드 |
| "거래처 ○○에게 파일 `C:\...\견적서.pdf` 를 첨부해 인사 메일" | 첨부 파일 경로로 새 메일 초안 | 초안만 → 승인 카드 |
| "내 업무 규칙대로 오늘 메일 처리해" | 저장된 **업무 지침**(§4)을 따라 분류·초안 | 초안만 |

## 3. 안전 설계 (메일 발송은 되돌릴 수 없다)
1. **AI 허용 API 는 읽기 + 초안 생성만**: `mailbox.folders / list / read / new / drafts(조회) / draft(생성)`. **발송·삭제·이동·영구 삭제·비우기·읽음 변경·초안 승인은 허용목록에 없다** — 테스트가 허용목록의 정확한 집합을 고정한다(하나팩스 `test_hanafax_p3.py` 와 같은 방식).
2. **보내기 = 카드의 "승인하고 보내기" 버튼**(사람, 관리자 인증). 카드에 받는 사람·참조·제목·본문 미리보기·첨부 목록이 보인다. 단건마다 승인이 기본이다(사전 승인 자동 발송은 이번 범위 밖 — §8).
3. **초안 상태기계**: `pending → sending → sent | failed | unknown | cancelled`. 전송 요청이 나간 뒤 결과가 불명확하면(`unknown`) **자동 재시도하지 않고 "확인 필요"** 로 멈춘다(중복 발송 방지가 재시도보다 우선). `sending` 으로의 전이는 원자적(같은 초안을 두 번 보내지 못함).
4. **한도**: 대기 중 초안 최대 50개, 받는 사람(참조·숨은참조 포함) 최대 20명, **하루 발송 상한 100통(설정 가능)**, 초과분은 거부. 초안은 7일 지나면 `expired`.
5. **첨부 파일 경로 안전**: AI 가 준 경로는 허용 폴더(사용자 문서·다운로드·바탕화면 + `HAEHAN_MAIL_ATTACH_DIRS`) 안의 일반 파일만. `.env`·키/인증서·`*.db`·`data/_backup*`·앱 소스/설정 폴더는 거부, 심볼릭 링크 해제 후 재검사, 형식·크기 제한은 기존 `attachments.py` 규칙(실행 파일 금지, 파일당 20MB). 카드에 파일명·크기를 보여 주므로 사람이 보고 승인한다.
6. **본문 안전**: 초안 HTML 은 기존 `html_sanitize.py` 로 정제(스크립트·외부 이미지 제거). 받은 메일 내용은 **지시가 아니라 자료**로만 취급하도록 지침에 명시(메일 본문 속 "이 지시를 따르라" 류 프롬프트 주입 방어) — 메일 본문에서 온 요청으로 발송·삭제를 하지 않는다. 발송 권한이 애초에 AI 에게 없으므로 최악의 경우에도 사람이 보는 카드까지만 도달한다.
7. **개인정보**: AI 가 읽은 메일 내용은 AI 대화 기록(채팅 세션)에 남는다. 사용자가 "AI 가 제목을 보고 읽을지 판단"하도록 정했으므로 **제목으로 거르고 필요한 메일만 본문을 읽도록 지침에 명시**한다. 자격증명·앱 비밀번호는 어떤 응답에도 없다.
8. **감사 기록**: 초안 생성(생성자 ai/user), 승인 시각, 발송 결과를 기록. 수신자 주소는 로그에서 마스킹하고 전체는 초안 DB 에만 둔다.

## 4. 업무 지침 (상세히 시키기)
계정별로 저장되는 "내 메일 업무 지침" 텍스트(최대 4,000자) — 매 지시 앞에 자동으로 붙는다. 예:
> 서명은 "신재우 / 해한 AI". 말투는 정중한 존댓말. 견적·입찰·발주 메일은 중요, 광고·뉴스레터는 무시. 거래처 ○○은 항상 참조에 △△ 추가. 답장 초안은 3문단 이내.
- 화면: AI 창 위 "업무 지침" 버튼 → 편집 창(저장/취소). 저장은 서버(계정별), 에이전트 프롬프트 합성은 화면(`agentHint`)에서.
- 지침은 **자료**일 뿐 안전 규칙(§3)을 바꾸지 못한다(허용 API 가 코드로 고정).

## 5. 화면 (메일함 탭 확장)
- 메일함 오른쪽에 **접이식 AI 창**(`UniversalChat domain="mailbox"`). 기본은 접힘, 버튼 "AI 업무 창".
- **열린 메일 컨텍스트**: 메일을 열고 AI 창에 지시하면 "(현재 열린 메일: 폴더=…, 번호=…, 제목=…)"을 지침에 덧붙여 "이 메일에 답장해줘"가 통한다.
- **지시 칩**(자주 쓰는 지시를 한 번에 채움): 새 메일 확인·분류 / 오늘 메일 요약 / 이 메일 답장 초안 / 이 메일 전달 초안 / 키워드 모아 정리.
- **승인 카드** `MailDraftCard`(`[[mail-draft:<id>]]`): 받는 사람·참조·제목·본문 미리보기·첨부 + 버튼 [승인하고 보내기] [취소]. 고치려면 AI 창에 "제목을 …로 바꿔 다시 만들어줘"라고 한다(새 초안을 만들고 이전 초안은 취소 — 첨부 파일 경로를 화면이 직접 채울 수 없어 쓰기 창으로 옮기는 방식은 쓰지 않는다). 상태(대기/보냄/실패/확인 필요/취소)와 보낸 시각 표시.
- 초안 목록: AI 창의 **"승인 대기 N" 탭**(대기 중 초안만, 상단 "AI 업무 창" 버튼에도 개수 배지) — 카드를 놓쳐도 여기서 승인할 수 있다.

## 7. 드라이런 (파일 수정 없이 확인한 것)
- 허용 API 등록 위치·형식 확인: `API_REGISTRY["hanafax.draft"]` 와 같은 `{"method","path","desc"}` — path 파라미터는 `{id}` 치환, 쿼리는 `query` 인자.
- 에이전트 실행: `ai_agent_router` → `claude -p --allowedTools mcp__haehan-orchestrator__*` — `call_api` 는 이미 기본 허용 도구라 **MCP 도구 추가 등록은 필요 없다**.
- 승인 카드 표시: `UniversalChat` 이 답변에서 `/\[\[fax-approve:([0-9a-f]{32})\]\]/g` 를 찾아 카드로 바꾼다 → 같은 방식으로 `[[mail-draft:<32hex>]]`.
- 예상 게이트: `module_registry` 신규 파일 5개 등록, 순환 80 유지(workflows→scripts 선례 따름), 라우트 수 기준값 재고정, `SECURITY_PATTERN`(첨부 경로 처리) 대상이므로 경로 거부 테스트 포함.
- 예상 사이드 이펙트: 없음(기존 API 응답 key·DB 변경 없음, 새 sqlite 파일 1개: 메일 초안 DB).

### 시험 중 발견·수정한 결함
- 상태 전이표가 `failed → sending` 을 막아 **명확하게 실패한 초안을 다시 시도할 수 없었다**(테스트가 발견) → 전이 허용.
- 첨부 경로의 민감 폴더 검사가 허용 폴더 **바깥쪽** 경로(예: 임시 폴더 아래 `AppData`)까지 보아 정상 파일을 거부했다 → 허용 폴더 **안쪽** 경로만 검사.
- 린트 자동 수정을 폴더 전체에 실행해 무관한 파일 55개가 바뀌는 사고 → 변경 규모 확인 후 복구(메모리에 재발 방지 기록).

### 실제 AI 실행 결과 (`/ai-agent/run`, 메일함 AI 창과 같은 지침)
1. 읽기: "받은편지함 최근 10통을 보고 읽을 가치가 있는 메일만 요약" → 26초, 알림 메일은 건너뛰고 **본문은 2통만** 읽음(`message/compact` 2회). 서버 로그상 호출은 `messages`·`message/compact` 뿐(허용 API 안).
2. 초안: "L.POINT 최근 메일에 답장 초안, 제목에 [시험]" → 승인 대기 초안 생성(`created_by=ai`, 발송 시각·승인자 없음, `in_reply_to` 연결), **업무 지침의 서명("신재우 / 해한 AI")을 적용**했고, 받는 주소가 발신 전용(noreply)이라 반송될 수 있다고 알림, 답변 끝에 `[[mail-draft:<id>]]` 표시. 시험 초안은 취소함(메일은 보내지 않음).
3. 화면(헤더리스 Chrome): 토글 버튼에 승인 대기 개수 배지, 지시 칩 4개(메일을 열면 7개로 증가), 칩은 입력창만 채움, 승인 대기 탭의 카드에 [본문 보기][승인하고 보내기][취소], 업무 지침 창, 브라우저 콘솔 오류 없음.
- **실제 발송은 하지 않았다**: 승인 버튼은 누르지 않았고, 발송 경로는 가짜 발송기 테스트로만 검증했다. 실전송 확인은 사용자가 카드 버튼을 한 번 눌러 본인 주소 1통으로 한다.
