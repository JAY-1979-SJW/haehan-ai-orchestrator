## 0. 소유권 원칙 — 지금은 내부 사용, 나중에 분리 판매 (2026-08-18 결정)

지금은 haehan-ai-orchestrator 앱에 **부속**시켜 운영한다(CDP 세션·크레덴셜·
capability_check·로깅 등 공용 인프라를 그대로 재사용하기 위함 — EUM/g2b/
스마트스토어와 같은 패턴). 단, **나중에 독립 제품으로 분리 판매할 계획**이 
있으므로, 이 모듈은 처음부터 "언제든 들어낼 수 있는 경계"를 유지한다.

**분리 경계(향후 추출 시 이 파일들만 옮기면 됨)**:
```
scripts/naver/blog_marketing/            ← 마케팅 파이프라인 본체
scripts/ops/blog_ai_batch_20.py          ← 신규 발행 CLI
scripts/ops/research_blog_topics.py      ← 주제 리서치 CLI
scripts/ops/blog_analytics_report.py     ← 성과 분석 CLI
docs/specs/naver_blog_content_standard.md ← 이 기준서
```

**격리 규칙(위반 금지)**:
- 위 파일들은 **다른 업무 도메인 모듈을 import하지 않는다** (EUM, g2b,
  스마트스토어, 하이웍스, 카카오워크 등). 2026-08-18 실측: 현재 의존성은
  전부 범용 인프라뿐(`scripts.logger`, `scripts.credentials`,
  `scripts.naver.automation.ai_responder`, `scripts.naver.blog.core.writer`,
  `scripts.naver.blog.management.analytics`, `scripts.naver.searchad`,
  `ai_orchestrator.connectors.naver_kin_client`, `ai_orchestrator.config`) —
  전부 "블로그/네이버 공용 엔진" 또는 "범용 유틸"이라 분리해도 안전함. 이
  상태를 유지할 것 — 새 기능 추가 시 다른 도메인 코드를 절대 참조하지 말고,
  필요하면 그 도메인의 범용 부분을 별도 공용 모듈로 뽑아서 참조.
- `data/blog_topic_*.json`, `data/reports/blog_analytics_*.json` 등 데이터
  파일도 이 모듈 전용 — 다른 도메인과 공유 스키마 쓰지 않는다.
- 신용정보(`scripts/credentials.py`)는 계속 공용으로 재사용(중복 구현 금지
  원칙 우선) — 분리 시점에 이 부분만 어댑터로 교체하면 됨.

## 2. 블로그 정체성 — "규정 설명"이 아니라 "AI 자동화 활용기"

이 블로그의 존재 이유는 "AI로 건설 실무(적산·물량산출·내역서·행정신고)를
자동화하는 프로그램을 만든다"는 걸 보여주는 것이다. 법령·절차를 친절하게
설명하는 일반 정보성 블로그가 아니다.

**흔한 실패(2026-08-17 실측)**: 프롬프트에 "AI 자동화 활용"을 요청해도
모델이 "실전 처리 절차"(사람이 손으로 하는 단계)로 되돌아가는 경우가 있었다.
9개 글이 이 상태로 발행됐다가 전면 재작성한 사고가 있었다 — 발행 전
`seo_check()`의 `ai_ratio` 경고를 반드시 확인할 것.

### 2.1 제목 규칙

- **제목에 "AI"라는 단어가 반드시 포함되어야 한다** (2026-08-17 사용자 지시).
  `content.py`의 `generate_post()`가 프롬프트로 요청하고, 없으면
  `"{title} (AI 자동화 활용법)"`으로 코드 레벨 강제 부착.
- 30~50자, 지식iN 질문 원문 어투를 살리되 자연스러운 블로그 제목으로 다듬기.

### 2.2 본문 구조 — 5단 구성, AI 섹션이 본체

```
1. 도입부           — 실제 질문/상황 인용            (~7%,  TARGET_BODY_CHARS 기준)
2. 핵심 개념·규정    — 딱 필요한 만큼만              (~10%)
3. [AI 자동화 활용]  — 본체. 반드시 70% 목표          (실측 상한 60~69%가 현실적)
4. 흔한 실수·주의사항 — AI 활용 시에도 사람이 확인할 점  (~8%)
5. 마무리            — 요약 + "관할 기관/전문가 확인 권장" (~5%)
```

**3번 섹션(AI 자동화 활용) 필수 요소**:
- 이 업무의 반복적·규칙적인 부분을 구체적으로 짚기(마감일 계산, 자동 판정,
  서식 자동 채우기, 데이터 조회·대조, 이력 관리 등)
- AI가 처리하는 실제 동작 순서를 최소 5단계, 번호를 매겨 각 2~3문장으로 서술
- 서로 다른 실제 활용 시나리오 2개 — 수작업 대비 처리 시간을 구체적으로 비교
- "저희 서비스를 이용하세요" 같은 직접 광고 문구 금지, 대신 AI 동작을
  최대한 구체적·기술적으로 묘사

**분량**: `TARGET_BODY_CHARS=3200`, `MIN_BODY_CHARS=2500` (2026-08-17 실측
상한에 맞춰 하향 조정됨 — 애초 목표였던 "A4 3장/3600자"는 모델이 꾸준히
2300~2900자로 수렴해 비현실적이었음). 분량보다 **AI 섹션 비중(60% 이상)**을
우선 기준으로 삼는다.

**확실하지 않은 수치·법령은 단정하지 말고 "확인이 필요합니다"로 표현.**
친절하고 정확한 어조 유지.

### 2.3 발행 전 SEO 체크 (`content.py::seo_check()`)

자동 경고(차단은 아님, 사람이 최종 확인):
- 제목 20~60자
- 본문 `MIN_BODY_CHARS` 이상
- 핵심 키워드가 제목에 포함, 본문에 2회 이상 출현
- 소제목(`##`) 구조 존재
- **`ai_ratio` ≥ 0.6** — `_ai_section_ratio()`가 계산.
  `## [AI 자동화 활용]` 대제목부터 다음 **`## ` (H2만, `### ` H3 제외)**
  대제목 전까지의 길이 / 전체 본문 길이. (2026-08-17: H3도 경계로 오인해
  1%대로 오탐하던 버그를 고침 — `re.match(r"^##\s", ...)`로 H2만 매칭)

## 4. CTA — 상품 판매 (2026-08-22 확정: 문의 유도 → 판매 유도로 전환)

**이 블로그는 트래픽이 목적이 아니라 우리 상품(AI 적산·물량산출·내역서
자동화 프로그램)을 파는 것이 목적이다.** "궁금하시면 문의해주세요" 같은
소극적 문구로 끝내지 않는다. 글 본문([전] 단계)에서 검색자의 실무 문제를
실제로 해결해준 다음, CTA에서는 **그 문제를 우리 제품이 어떻게 푸는지
구체적 증거(화면 캡처·실측 수치)로 보여주고, 구매/제안 페이지로 직접
연결**한다.

```
## 📌 [주제]를 매번 손으로 하기 번거로우시죠

· [실측 수치 1 — 예: 호표 수·인식률·적발 사례 등, 지어내지 않은 것만]
· [실측 수치 2]
· [실제 화면 캡처 또는 프롬프트/입력 예시]

👉 [제품에 맞는 페이지로 연결 — 아래 참조]
```

- CTA 링크는 **주제와 매칭되는 제품 페이지**를 쓴다. 무조건
  `https://haehan-ai.kr`(홈페이지 최상단)로 뭉뚱그리지 않는다.
  - 물량산출/도면 인식 관련 주제 → `https://haehan-ai.kr/quantity-proposal.html`
  - 그 외 제품 페이지가 없는 주제는 홈페이지(`https://haehan-ai.kr`)를 쓰되,
    발행 전 반드시 실제 URL이 살아있는지 확인한다(추측으로 링크 만들지 않음).
- 못하는 것도 정직하게 쓴다(정확도 낮은 항목 등) — 신뢰가 있어야 전환된다.
- **전화번호 노출 정책 변경(2026-08-22, 2026-08-23 재확인)** — 기존
  "전화번호 미노출"(2026-08-17)을 뒤집는다. CTA 블록에 `010-7387-6635`를
  명시한다. 문의 문턱을 낮추는 게 링크 클릭 유도보다 전환에 유리하다고 판단.
  **단, 요지는 번호 자체가 아니라 "왜 우리에게 연락해야 하는가"다** — 번호를
  던지기 전에 반드시 위 CTA 템플릿의 실측 수치·화면 캡처로 "우리가 이
  문제를 이렇게 푼다"를 먼저 증명한다. 번호는 그 증명 다음에 오는 마지막
  줄이지, 증명을 생략하고 번호부터 내미는 CTA는 이 기준서 위반이다.
- **브랜드 표기 (2026-08-23 확정)** — CTA·본문에서 회사/브랜드명을 쓸 때는
  반드시 **"해한 AI"**로만 쓴다. "해한 AI 엔지니어링"(과거 EUM 영업메일 등에
  쓰던 정식 상호) 표기는 이 블로그에 쓰지 않는다.
- **CTA의 목표 (2026-08-23 확정)** — CTA는 "방문"이나 "링크 클릭"에서 끝나면
  안 된다. 독자가 **전화를 걸어서 말하는 것**까지가 목표다. 아래 두 가지 중
  하나를 유도한다:
  1. "이 프로그램을 우리 회사에 도입하고 싶다" (제품 구매/계약 문의)
  2. "이 프로그램을 직접 다뤄보는 개인 교습을 받고 싶다" (개인 강습 문의)
  CTA 문구는 이 두 가지를 명시적으로 제안한다("도입하고 싶으시거나,
  직접 다뤄보고 싶어서 개인 교습을 받아보고 싶으시면 연락 주세요" 형태) —
  막연히 "궁금하시면 연락 주세요"로 뭉뚱그리지 않는다.
- **유튜브 연동 (2026-08-20 변경)** — 기존에는 "유튜브 링크를 넣지 않음"이었으나,
  유튜브 채널(`@해한ai`) 운영을 시작하면서 사용자가 교차 노출을 명시 요청했다.
  방식은 **C(둘 다)** 로 확정:
  1. **영상 파일을 네이버에 직접 업로드**한다(`writer.insert_video()`).
     네이버는 자사 동영상을 검색에서 우대하므로 링크만 걸면 손해다.
  2. **유튜브 링크는 본문 하단에 1회만.** 남용하면 광고 글이 되어 D.I.A 점수가
     떨어진다. 위치·횟수를 못박는 이유다.
  - 영상 배치는 **[전] 실무 답변 뒤, [AI로 하면] 앞**. 맨 위에 두면 글을 읽기
    전에 재생하고 이탈해 체류시간이 깨진다.
- 이미지 3장 인터리브 후 4번째 텍스트 블록(이미지 없음)으로 자연스럽게 붙음.
- **참고**: 현재 자동화는 일반 텍스트로만 삽입한다. Naver SE3 에디터에서
  폰트 크기를 실제로 키우는 자동화(텍스트 선택 → 폰트크기 UI 조작)는
  아직 구현되어 있지 않음 — "크게 보이게"는 지금은 별도 문단 분리 +
  이모지(📌 👉)로만 시각적 강조. 진짜 폰트 확대가 필요하면 별도 요청.

## 4.1 네이버 블로그 정책 준수 (저품질 판정 방지, 2026-08-23 추가)

이 블로그는 상업적 목적(제품 판매)이 명확하지만, 그렇다고 저품질/스팸으로
판정되면 검색 노출 자체가 죽어 목적을 못 이룬다. 웹 조사(2026-08-23) 기준
지켜야 할 선:

1. **"광고성 글 비중 30% 이하" — 이 지표는 협찬/체험단 글에 적용되는
   기준이지, 우리 방식과는 성격이 다르다는 걸 구분한다.** 웹 조사에서 나온
   30% 가이드라인은 원래 "블로그 전체 글 중 대가를 받고 쓴 협찬·체험단
   리뷰의 비율"을 말한다. 이 블로그는 협찬을 받지 않는다 — 자기 제품을
   자기 블로그에서 소개하는 것이라 그 지표가 그대로 적용되진 않는다.
   그래도 **매 글마다 CTA가 붙는 건 사실**이니, 저품질 판정을 피하려면
   같은 정신(광고가 본문을 압도하면 안 된다)을 지킨다:
   - [기][승][전][결] 본체(실무 답변)가 **진짜 답이어야 한다** — CTA를
     달기 위한 구실용 본문이면 안 된다.
   - CTA는 **본문 끝 한 블록에만** 그친다(위 4번 섹션 템플릿 분량 이내).
     본문 중간에 CTA성 문장을 끼워 넣지 않는다.
   - 협찬 표기 의무(문구 삽입 등)는 우리 경우엔 해당 사항 없음 — 협찬이
     아니라 자사 제품이기 때문. 다만 명백히 광고처럼 읽히는 문장("최고의",
     "무조건", "지금 안 사면 손해")은 피한다 — 신뢰가 전환을 만든다는
     이 기준서의 대원칙과도 배치된다.
2. **본문 내 상업적 외부 링크를 남발하지 않는다.** 글 하나당 제품 페이지
   링크 1개 + 문의처(홈페이지·전화) 정도로 제한한다. 문단마다 링크를 박지
   않는다.
3. **키워드를 억지로 반복하지 않는다.** SEO를 노린다고 같은 단어를 문단마다
   기계적으로 반복하면 품질 평가에서 불이익을 받는다. 자연스러운 동의어·
   풀어쓰기를 쓴다.
4. **AI가 티 나게 쓴 것처럼 보이면 안 된다.** 네이버는 "실제 경험 없이
   작성된 광고성 글"을 걸러내겠다고 공식 발표했다 — 이 기준서 전체(실측
   수치·화면 캡처·정직한 한계 고백)가 바로 이걸 피하기 위한 장치다. 지어낸
   숫자·경험담은 절대 금지(위 2번 "미검증 수치 경고" 참고).
5. **분량은 1,500자 이상, 완독 가능한 밀도로.** 글자수를 채우려 일반론을
   늘어놓지 않는다(`MIN_BODY_CHARS`는 1,200자로 하한만 잡아두고 실제로는
   내용이 있으면 그 이상 자연히 늘어나게 둔다).
