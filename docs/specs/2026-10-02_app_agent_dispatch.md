# 앱 AI 에이전트 작업 분배(멀티 실행) — 기준서 (초안, 승인 대기)

- 날짜: 2026-10-02 / 사용자 요청: "AI 에이전트 작업 시 멀티창으로 작업 분배 가능해? → 앱이 되게 분배해"
- 선행 확인: `capability_check ai-agent` — 기존 구현 없음(분배 기능). 실행 경로는 기존 것을 재사용한다: `POST /api/v1/ai-agent/run` → `local_agent_registry` 작업 큐 → `local_agent`(WebSocket) → `claude -p`. **새 큐·새 프로세스 체계를 만들지 않는다.**

## 1. 현재 구조에서 실측한 한계 (코드 확인)
| 항목 | 확인 결과 | 위치 |
|---|---|---|
| 작업 실행은 **직렬** | 에이전트가 작업 하나를 받으면 `await asyncio.to_thread(process_task, task)` 가 끝날 때까지 다음 메시지를 받지 않는다 → 에이전트 1개 = 동시 1작업 | `local_agent/websocket_client.py:451` |
| 등록된 에이전트 **1개** | `la-e6b19039392c`, 현재 `offline`(로컬 에이전트 프로세스가 꺼져 있음) | `GET /api/v1/local-agents` |
| 에이전트 선택 | idle 우선, 없으면 첫 번째(큐에 쌓임) — 용량 개념 없음 | `routers/ai_agent_router.py:run_agent` |
| 분배·의존·자원 충돌 관리 | 없음 | — |
→ 지금은 여러 요청을 넣어도 한 줄로 순서대로 처리된다. "멀티창 분배"를 하려면 ① 동시 실행 ② 충돌 관리 ③ 분배 계획 ④ 화면이 필요하다.

## 2. 설계 원칙
1. **분배안은 AI 가 제안하고 사람이 승인한 뒤에만 실행**(승인 전에는 아무 작업도 시작하지 않는다).
2. **충돌하는 자원은 병렬로 돌리지 않는다.** 프로젝트 규칙 "병렬 금지: git, DB, 배포, 서버 재시작, 파일 삭제, 권한 변경, secret 작업, 같은 파일 수정"을 코드로 강제(§4). 화면·마우스·CDP 창 조작도 한 번에 하나(오늘 겪은 충돌 사례).
3. **쓰기 작업은 격리 폴더(git worktree)에서 실행**하고 결과는 브랜치로 남긴다. **병합은 직렬이며 사람이 승인**한다(같은 작업 폴더 공유로 생긴 이력 충돌 방지).
4. **동시 실행 수 기본 2, 최대 3**, 작업별·전체 비용 상한(`max_budget_usd`)을 합산해 제한. 메모리 부족 이력(백그라운드 작업 강제 종료)이 있어 PC 여유 메모리가 기준 미만이면 새 작업을 시작하지 않는다.
5. 외부 유료 AI API 는 쓰지 않는다(사용자 본인의 Claude Code `claude -p` 만, 기존 `run_claude_agent` 와 동일). 병렬화로 비용이 늘어나므로 상한이 필수.

## 3. 구성 (단계 P1~P5, 직렬 진행)
| 단계 | 내용 | 계층·파일 |
|---|---|---|
| **P1 동시 실행** | 로컬 에이전트가 `LOCAL_AGENT_MAX_PARALLEL`(기본 1=현재와 동일, 설정 2~3) 개 작업을 동시에 처리. 작업마다 스레드, 결과 전송은 락으로 직렬화, 하트비트 유지, `capacity`/`active_task_count` 보고. 서버는 용량이 남은 에이전트를 우선 선택 | `local_agent/websocket_client.py`(수정, 병렬 수 1 이면 기존 경로 그대로), `local_agent_registry_agent.py`(capacity 필드 추가), `routers/ai_agent_router.py`(선택 규칙) |
| **P2 충돌 정책(순수)** | 작업이 선언하는 자원 `{git, db, server, deploy, ui, cdp:<사이트>, path:<경로>}` 로 서로 겹치면 직렬, 겹치지 않으면 병렬. 읽기 전용 작업은 자유. 금지선(§4) 하드코딩. 스케줄 순서 계산 | `gates/agent_dispatch_policy.py`(신규, L2, I/O 없음) |
| **P3 분배 서비스·API** | `POST /ai-agent/dispatch {goal}` → 계획 단계(읽기 전용 `claude -p` 가 하위 작업·자원·예상 비용을 JSON 으로 제안, **미승인 상태로 저장**) → `POST /dispatch/{id}/approve`(사람) → 정책이 허용한 만큼 동시 실행 → `GET /dispatch/{id}` 진행 상황, `POST /dispatch/{id}/cancel`. 종료 시 결과 요약 | `services/agent_dispatch_service.py`, `persistence/agent_dispatch_store.py`(sqlite), `routers/agent_dispatch_router.py`(관리자 전용) |
| **P4 쓰기 작업 격리** | 파일을 바꾸는 하위 작업은 `git worktree`(짧은 경로 `C:\hhwt-<id>`, 임시 브랜치)에서 실행, 완료 시 브랜치·변경 요약만 보고. 병합은 사람이 카드에서 승인한 뒤 직렬로 1개씩 | `workflows/agent_dispatch_worktree.py`(신규, git 은 서버 PC 로컬만) |
| **P5 화면** | AI 콘솔에 "작업 분배" 패널: 목표 입력 → 분배안 카드(하위 작업·자원·병렬/직렬 표시·비용 상한) → [승인하고 시작] → 진행 보드(대기/실행/완료/실패, 작업별 로그) → 결과·병합 카드 | `admin-web/src/app/…`(신규 컴포넌트, UniversalChat 와 같은 카드 방식) |

## 4. 병렬 금지 목록(정책이 강제, 승인해도 못 푼다)
- **항상 직렬(전역 락)**: git(commit·push·rebase·병합), DB 쓰기·스키마, 서버 재시작·배포, 파일 삭제, 권한 변경, secret·키 작업.
- **한 번에 하나**: 화면·마우스·키보드 조작(`ui`), 같은 사이트의 CDP 세션(`cdp:<사이트>`), 같은 경로를 쓰는 작업(`path:`).
- 하위 작업이 자원을 선언하지 않았거나 판정이 모호하면 **직렬로 취급(fail-closed)**.
- 외부 공개 발행·메일/메시지 전송·결제는 분배 실행 중에도 **각각 기존 승인 절차를 그대로** 거친다(분배 승인이 그것을 대신하지 않는다).

## 5. 안전·비용
- 계획 단계 에이전트는 읽기 전용 도구만 허용(허용 목록 고정, 테스트로 강제). 분배 API 자체는 AI 가 호출하지 못한다(`mcp_server.API_REGISTRY` 에 넣지 않음, 메일 대량 발송과 같은 방식).
- 한도: 하위 작업 수 최대 6, 동시 최대 3, 전체 비용 상한 기본 $6(작업당 기본 $1), 시간 제한(작업당 기본 5분, 최대 30분). 상한 도달 시 남은 작업은 시작하지 않고 `skipped`.
- 실패 처리: 하위 작업 하나가 실패해도 독립 작업은 계속, 의존 작업은 건너뜀. 재시도는 사람이 선택(자동 재시도 없음).
- 로그에는 prompt 전체 대신 요약만, 비밀번호·토큰·`.env` 값 불포함.

## 6. 드라이런으로 확인할 것 (승인 후 코드 전에)
1. 가짜 `process_task`(sleep) 로 P1 을 시험해 동시 N 개 처리·결과 순서·하트비트 유지·연결 끊김 시 실행 중 작업 처리 확인(기본값 1 에서 기존 테스트 전부 통과해야 함).
2. P2 정책 단위 시험: 금지 목록·겹침·모호함(fail-closed)·읽기 전용 병렬.
3. P4 는 임시 저장소로 worktree 생성·정리·충돌 시험(실제 프로젝트 브랜치 미접촉).
4. 게이트 예상: 신규 파일 레지스트리 등록, 라우트 +N(기준값 재고정), 모듈 순환 유지, `local_agent` 층에서 `ai_orchestrator` 역방향 import 금지.

## 7. 범위 밖
- 여러 PC 에 걸친 분산 실행(에이전트 1대 PC 안에서의 병렬만), 클라우드 원격 실행.
- 창 조작 자동화(마우스·키보드) 병렬화 — 한 번에 하나만.
- AI 가 스스로 새 하위 에이전트를 무한 생성하는 구조(상한 고정).

## 8. 결정 대기 (권장안)
1. 동시 실행 기본 **2**, 최대 3 — 권장(메모리 이력).
2. 쓰기 작업은 **worktree 격리 + 병합은 사람이 승인** — 권장.
3. 비용 상한 전체 **$6**, 작업당 $1 — 권장(앱 기존 기본값 $2/작업보다 낮게).
4. 로컬 에이전트가 현재 꺼져 있다 — P1 시험·운영에는 `python -m local_agent.agent --run` 실행이 필요(제가 필요할 때만 켜고 끝나면 끈다).
