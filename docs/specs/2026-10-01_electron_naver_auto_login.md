# Electron 앱 네이버 자동 로그인 — 기준서 v1

- 날짜: 2026-10-01 / 상태: **구현·검증 완료(서버 재시작 전).** 자동 로그인 전 과정을 실제 브라우저에서 성공 확인, 화면·API 는 서버 재시작 후 종단 확인 예정
- 사용자 요청: "일렉트론 앱에서 자동 로그인 되게 해봐" · 결정: ① 기본 계정 **skyjwsin** ② **로그아웃 상태면 화면을 열 때 자동 1회**
- 관련: `docs/specs/2026-09-30_blog_auto_writing_automation.md` §4 "로그인 절차"(같은 정책을 앱 화면에도 적용)

## 1. 현황 (실측, 2026-10-01)
| 사실 | 내용 |
|---|---|
| 경로는 이미 있다 | Electron(`shell.html` 이 `localhost:3000` Next.js 를 webview 로 로드) → `/naver/session` 화면 "로그인" 버튼 → `POST /api/v1/naver/session/login` → `run_naver_login_pipeline(naver_id=None)` |
| **버튼은 다른 계정으로 로그인한다** | 저장된 계정: `naver`(= `bigsun2024`), `naver:skyjwsin`, `naver:skyjswin`(오타로 보이는 중복 항목). 화면은 계정을 지정하지 않아 기본(`bigsun2024`)으로 시도. 2026-09-30 자동 로그인 시도 때 아이디 칸에 미리 들어 있던 10자 값이 이 아이디다 |
| 상태 표시가 실제가 아니다 | `GET /naver/session/status` 는 저장된 파일(`load_session_status`)만 읽어, 사용자가 직접 로그인해도 "미로그인"으로 남을 수 있다 |
| **이미 로그인된 상태도 실패 처리** | `login_naver` 의 "이미 로그인됨" 분기가 사용자명을 비교하는데, 요소 기준 판정에는 사용자명이 없어(`None`) 올바르게 로그인돼 있어도 `different_user_logged_in` 로 실패 |
| 프론트 반영 | Electron 은 Next.js 서버를 그대로 불러오므로 화면 변경에 asar 패치·재빌드가 필요 없다(`main.js`·`shell.html` 을 바꾸지 않는 한) |
| 계정 확인 수단 | 블로그 관리 주소의 공개 alias(`admin.blog.naver.com/{alias}/`) — `skyjwshin` 은 로그인 ID 와 alias(`beautiful-light`)가 달라 하이픈 정규식 사고 이력(2026-08-24) |

## 2. 정책 (앱 화면 = 자동화와 같은 규칙)
화면을 열면 ① 읽기 전용으로 상태 판정(보이는 요소 + 세션 쿠키 이름) ② 계정 확인(새 탭에서 블로그 alias 읽고 닫음).
| 판정 | 동작 |
|---|---|
| `in` + 대상 계정 alias 일치 | 아무것도 하지 않음("로그인됨·계정 확인") |
| `in` + 다른 계정 | 건드리지 않음. "다른 계정(alias)으로 로그인돼 있음" 표시(전환하려면 로그아웃이 필요해 자동으로 하지 않음) |
| `in` + alias 확인 불가 | 건드리지 않음. "로그인됨(계정 미확인)" |
| `unknown` | 시도 안 함("상태 불명확") — 살아 있는 세션 파기 방지 |
| **`out`** | 대상 계정(기본 skyjwsin)으로 **자동 로그인 1회**. 시도 제한: 마지막 시도 후 5분 대기, 하루 3회. 캡차·2단계 인증은 즉시 중단(사용자 처리 대기 표시) |
- 로그아웃 URL 이동·쿠키 삭제는 어떤 경우에도 하지 않는다. 자격증명은 읽어도 출력·저장하지 않는다.
- 같은 화면 방문에서 자동 시도는 1번뿐이고, 이후는 버튼(같은 제한·같은 안전 조건)으로만.

## 3. 변경
| 대상 | 내용 |
|---|---|
| 신규 `scripts/naver/blog/automation/account_probe.py` | 블로그 alias 읽기(하이픈 포함)·alias→계정 매핑. 블로그 자동 작성 C단계 사전 조건도 같은 함수를 쓴다 |
| 신규 `ai_orchestrator/workflows/naver_session_guard.py` | `observe()`(읽기 전용 상태+계정), `may_attempt()`(대기·횟수 제한, 순수), `ensure_login()`(위 표대로 결정, 파이프라인은 `out` 일 때만) |
| 수정 `ai_orchestrator/connectors/naver_session_router.py` | `GET /live`, `POST /ensure` 추가. 기존 `/status`·`/login` 은 그대로(다른 호출자 보호) |
| 수정 `scripts/naver/auth.py` | 로그인돼 있는데 사용자명을 모르면 "다른 사용자"가 아니라 `logged_in_account_unknown` 으로 보고 |
| 수정 `admin-web/src/app/naver/session/page.tsx` | 실제 상태·계정 표시, 계정 선택(기본 skyjwsin), 열 때 자동 1회, 버튼은 `/ensure` 사용 |
| 데이터 | `data/naver_login_attempts.json`(시도 시각·대상·결과, 자격증명 없음) |

## 4. 검증 계획
- 단위: 시도 제한, `ensure_login` 전 분기(파이프라인은 `out` 에서만 호출, 로그아웃 호출 없음), alias 추출(하이픈), 라우터 권한·오류, `auth.py` 분기.
- 실제 화면(읽기 전용): 지금 로그인된 세션에서 `observe` → `in`·alias 확인. **자동 로그인 전 과정은 로그아웃 상태에서만 볼 수 있어** 세션 자연 만료 시 확인(메모리 `naver-auto-login-unverified`).
- 프론트: `npm run typecheck`.

## 4-1. 실제 검증 결과 (2026-10-01)
- **자동 로그인 전 과정 성공.** 세션이 자연 만료돼 `out`(로그인 버튼 3개·쿠키 없음)이 된 상태에서(제가 로그아웃한 것이 아님, 브라우저 재시작 없음) 지킴이 경로(`ensure_login("skyjwsin")`)로 1회 실행 → 아이디·비밀번호 입력, 제출, 로그인 성공(`user=skyjwsin`), 세션 저장. 27초. 시도 기록 1건(`result: ok`).
- 이후 읽기 전용 확인: `state=in`, 세션 쿠키 있음, 블로그 alias `skyjwsin` → **계정 확인됨**.
- 이 실행에서 결함 1개 발견·수정: 로그인 직후 페이지 이동 중에 상태를 읽어 `unknown` 이 나와 성공을 "실패"로 보고했다 → 안정될 때까지 최대 6회(3초 간격) 다시 읽고, 끝내 불명확하면 "실패"가 아니라 `unverified`("로그인은 성공한 것으로 보이나 화면에서 확인하지 못했습니다")로 보고.
- 자동 채우기 값: 첫 시도에서 아이디 칸에 미리 들어 있던 10자는 기본 저장 계정 `bigsun2024` 의 아이디였다(제출 전에 멈췄고 이번에는 지우고 `skyjwsin` 으로 재입력됨).
- 단위 테스트 74개(지킴이 45+, 라우터 19, 입력 시간·마스킹 7 등), 변이 시험 14개 전부 검출, 화면 타입체크·린트 통과.
- **아직 못 한 것:** Electron 화면의 버튼·자동 시도를 실제 화면에서 눌러 보는 종단 확인 — 8401 서버가 어제 뜬 옛 프로세스라 새 엔드포인트(`/live`, `/ensure`)가 없어 서버 재시작(승인 필요) 뒤에 한다.

## 5. 위험·한계
- 계정 확인은 블로그 관리 주소를 새 탭으로 읽는다 — 블로그가 없는 계정이면 확인 불가로 표시(동작은 안 막음).
- 저장된 `naver:skyjswin`(오타 추정)은 삭제하지 않는다(데이터 삭제는 별도 승인).
- 화면 종단 확인은 서버 재시작 뒤에 한다(위 4-1).
