# 사이트 업무 지도(Site Task Map) — 기준서 (승인 대기, 코드 없음)

- 날짜: 2026-10-03 / 사용자 요청: "처음 보는 사이트도 앱이 탐색해 **필요한 업무를 기록·분류해서 지도로 만들고 저장**, 다음에 에이전트 앱이 **그걸 참조해서 처리**". 사이트 안에서의 **대량 조회는 허용**(사용자 확인).
- 배경: 공무 G3(KISCON 등)·EUM·스마트스토어에서 같은 사이트를 세션마다 처음부터 탐색해 토큰·시간을 낭비. 저장소의 `scripts/explorer/*` 는 URL/폼 구조는 저장하지만 **저장물을 읽는 쪽이 없다**(2026-10-03 grep 실측: 소비자 없음).
- 실행 주체는 **앱**(Claude Code 아님). Claude Code 는 이 기능을 개발·점검하는 도구일 뿐이다.

## 1. 핵심 개념: URL 지도가 아니라 "업무 지도"
기존 사이트맵(`data/sitemap`, `data/manual_visits`)은 *화면* 단위다. 에이전트가 필요한 것은 *업무* 단위다.

| 항목 | 예 (KISCON 공개 조회) |
|---|---|
| 사이트(host) | `www.kiscon.net` — 로그인: 불필요 / 공동인증서 / ID·비밀번호 |
| **업무(task)** | `업체정보 검색` — 분류: 조회 / 입력 / 제출 / 다운로드 |
| 목적·쓰임 | "하도급 상대 업체의 상태·등록업종 확인(공무 P3)" |
| **절차(steps)** | ① `/gongsi/ksc_dft.asp` 열기 ② `txtSangHo`(업체명) 입력 ③ 검색 `send('gongsi_list', frm1)` ④ 결과 표 읽기 |
| 입력 필드 | 이름·종류·필수 여부·예시(값은 저장하지 않음) |
| 출력 | 표 열 이름(상호·업체상태·등록업종…), 페이지네이션 방식 |
| **위험 등급** | `read`(조회) / `write`(저장·수정) / `submit`(제출·신고·결제·삭제 — 자동 실행 금지, 사람 승인) |
| 로그인 요건 | 공개 / 로그인 / 인증서(사용자만) |
| 검증 상태 | `observed`(탐색에서 봄) → `verified`(실제로 한 번 성공 실행) → `stale`(재확인 필요) |
| 근거 | 탐색 일시, 마지막 성공 일시, 실패 이력, 화면 지문(필드 이름 해시) |

### 1-1. 표준 활용 (2026-10-03 반영 — 저장 형식은 JSON, 가능한 한 기존 규격 재사용)
| 층 | 채택 | 적용 |
|---|---|---|
| **steps** | Chrome DevTools Recorder JSON(= Puppeteer Replay) 단계 형식 호환 (`navigate`·`click`·`change`·`waitForElement`·`selectors`) | 업무의 `steps` 배열을 이 형식으로 저장 → DevTools 로 사람이 녹화한 절차를 가져오기/내보내기 가능. 자체 포맷을 새로 만들지 않는다 |
| **요소 지정** | ARIA 역할·접근성 이름(Playwright `getByRole`/`getByLabel`) + 폼 `name`/`id` 병행 저장 | CSS 클래스에만 의존하지 않는다. 화면 지문(필드 이름 해시)과 함께 `stale` 판정에 사용 |
| **HTTP 호출(선택)** | HAR 기록 + OpenAPI 초안 | M3 탐색 시 XHR 를 HAR 로 함께 남길 수 있다(선택, **토큰·쿠키·Authorization 헤더·응답 본문은 제거 후 저장**). 안정적인 read 호출이 확인된 업무만 화면 조작을 호출로 대체 후보로 표시. 사이트 약관·봇 정책 확인 전에는 대체하지 않는다 |
| **업무 흐름(선택)** | Arazzo(OpenAPI Initiative) 호환 가능성만 열어 둠 | 여러 호출이 이어지는 업무를 HTTP 로 대체하게 될 때 검토. 지금은 미채택 |
| **에이전트 노출** | MCP (`mcp_server.API_REGISTRY` 기존 방식) | 지도 업무를 도구로 내보내는 길은 M2 이후 |
| **이 프로젝트 고유(표준 없음)** | 업무 단위 묶음, 위험 등급(`read`/`write`/`submit`), 검증 상태(`observed`/`verified`/`stale`) | 직접 정의. 안전 장치의 핵심이므로 L1 순수 모듈에서 시험으로 고정 |
- 각 규격의 최신 버전·세부 필드는 채택 시점(M1 구현 직전)에 공식 문서로 재확인한다(이 문서는 기억 기반 요약).

## 2. 흐름
1. **탐색**: 사용자가 사이트 로그인(인증서·OTP 는 사람) → 앱이 읽기 전용으로 메뉴·화면을 돌며 화면별 폼·표·버튼 수집. 기존 `auto_explorer`·`page_snapshot`·`page_classifier`·`bot_radar` 를 **재사용**(신규 크롤러 만들지 않음). 대량 조회 허용 — 단 **제출/삭제/결제 버튼 클릭 금지**, 봇 감지(캡차·차단)가 보이면 즉시 중단.
2. **분류**: 화면 → 업무로 묶는다(규칙 기반: 폼+표=검색 업무, 입력폼+저장버튼=입력 업무, 제출 키워드=submit 등급). 모호한 것은 `unclassified` 로 두고 AI 가 제안 → 사람이 확정(조용한 추측 금지).
3. **저장**: 호스트별 JSON 하나(`data/site_task_map/<host>.json`, 버전 필드 포함). 데이터 행·입력값·쿠키·토큰은 저장하지 않는다(구조만).
4. **참조**: 에이전트가 사이트 작업을 시작할 때 `sitemap.lookup(host, 키워드)` 로 업무 후보·절차를 받아 **그 절차대로 실행**. 지도에 없으면 탐색을 제안(사용자 승인).
5. **갱신**: 실행이 성공하면 `verified`, 필드/URL 불일치로 실패하면 `stale` 표시 후 재탐색 제안. 틀린 지도를 조용히 계속 쓰지 않는다.

## 3. 구성 (신규 파일 위치)
| 계층 | 파일 | 역할 |
|---|---|---|
| L1 | `ai_orchestrator/domain/site_task_map.py` | 스키마·분류 규칙·위험 등급 판정(순수, 시험 용이) |
| L7 | `ai_orchestrator/persistence/site_task_map_store.py` | 호스트별 JSON 읽기/쓰기(원자적 저장, 버전) |
| L3/L4 | `scripts/explorer/task_mapper.py` | 기존 explorer 결과(`data/sitemap`, `manual_visits`)를 업무 지도로 변환 + 탐색 실행 어댑터 |
| L6 | `ai_orchestrator/services/site_task_map_service.py` | 탐색 요청·분류 확정·검증 상태 갱신 |
| L8 | `ai_orchestrator/routers/site_task_map_router.py` | `/site-map/*` (관리자 전용) |
| AI | `mcp_server.API_REGISTRY` | `sitemap.lookup`·`sitemap.list`(읽기), `sitemap.explore`(**승인 카드**로만 시작), 확정·삭제는 허용 안 함 |
| 화면 | `admin-web` 사이트 지도 보기(호스트 → 업무 목록 → 절차·위험 등급·검증 상태, 분류 확정) | |
| 기존 입력 | `data/sitemap/*.json`, `data/manual_visits/*` 를 가져와 초기 지도 생성(EUM 사이트맵 포함) | |
- 도메인 간 직접 import 금지 준수: 지도는 공용 모듈, 공무·EUM 등은 `lookup` API 를 통해서만 사용.

## 4. 안전 규칙
- 허용: 조회성 이동·검색·조회 반복(대량 허용). 호출 간 최소 간격과 일일 상한은 **설정값**(기본 1초·500페이지/세션)으로 두고 사용자가 올릴 수 있다.
- 금지(코드가 막음): `submit` 등급 요소 클릭, 삭제·결제·송금·전자서명, 로그아웃·쿠키 삭제(세션 보존 원칙), 인증서·비밀번호 읽기.
- `write`/`submit` 업무는 지도에 기록만 하고 **실행은 사람 승인 카드**(메일·공무 초안과 같은 방식).
- 저장물은 `data/` 아래(gitignore). 저장소가 PUBLIC 이므로 지도 파일을 커밋하지 않는다. 시험용 픽스처는 가상 구조만.
- 로그인 후 화면의 개인정보·금액은 저장하지 않는다. 필드 이름·열 이름·URL 패턴만.

## 5. 단계 (직렬)
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M1 | (착수 전 Recorder JSON·ARIA 규격 공식 문서 재확인) L1 스키마·분류 규칙·L7 저장 + 단위 시험. 기존 `data/sitemap`·EUM 사이트맵을 변환해 초기 지도 | 변환 시험, 위험 등급 경계 시험 |
| M2 | 조회 API(`/site-map`) + 에이전트 허용 `sitemap.lookup/list` + 공무 AI 창 지침에 "먼저 지도 조회" 연결 | 허용 집합 고정 시험, 실제 호출 1회 |
| M3 | 탐색 실행(`sitemap.explore` 승인 카드) — KISCON 공개 화면으로 실사이트 시험. HAR 수집은 선택 항목 | 실탐색 → 지도 생성 → 다음 호출에서 참조 확인 |
| M4 | 화면(지도 보기·분류 확정), 검증/stale 갱신 | 타입체크·ESLint·게이트 3종 |
- KISCON 공개 조회(`2026-10-03_gongmu_g3_kiscon.md` §7)는 M3 의 첫 실사례로 흡수 가능. 인증서 보유 후 CWS(대장 통보)도 같은 방식으로 지도에 추가.
