# 메일 순차 대량 발송 — 기준서 (초안, 승인 대기)

- 날짜: 2026-10-02 / 사용자 지시: "대량 발송은 한 번에가 아니라 **순차적으로** 대량 발송하게 조정" (연락처 최대 1천~수천 명)
- 선행 확인: 하나팩스 발송 승인서가 같은 문제를 이미 푼 구조(`2026-10-02_hanafax_auto_send.md`)다. **같은 뼈대를 재사용하고 새 방식을 만들지 않는다.** 재사용 부품 — 정책 `gates/fax_send_policy.py`(판정 SEND/SKIP/DENY, 한도·시간대·중복·수신거부·정지), 저장소 `persistence/fax_authorization_store.py`(승인서·발송 로그·수신거부·정지 스위치), 실행기 `workflows/hanafax_auto_send.py`(회차 실행, 이어 보내기), 서비스 `services/hanafax_authorization_service.py`(주소록 가져오기·승인·취소·즉시 실행), 예약 작업 `hanafax_send`.
- 전제: 메일 보내기(SMTP)·초안 카드·AI 창은 구현됨(`2026-10-02_mailbox_ai_window.md`). 이 기능은 그 위에 "수신자 목록 × 같은 내용"을 **한 명씩 차례로** 보내는 층을 더한다.

## 1. 핵심 원칙: 한 번에가 아니라 차례로
| 원칙 | 내용 |
|---|---|
| 1통 1수신자 | 받는 사람 칸에 여러 명을 넣지 않는다(주소 노출·일괄 반송 방지). 수신자마다 **별도 메일 1통** |
| 간격 | 한 통 보낸 뒤 **간격(기본 30초, 설정 가능, ±20% 무작위)** 을 두고 다음 사람. 한꺼번에 연결을 여러 개 열지 않는다(연결 1개, 동시 발송 없음) |
| 회차·일일 상한 | 회차당 최대 N통, 하루 최대 M통(기본 **하루 200통**, 승인서에서 설정, 계정 한도 확인 뒤 조정). 상한에 닿으면 **멈추고 다음 날 이어서** |
| 이어 보내기 | 중단·서버 재시작·상한 도달 후에도 **이미 보낸 사람은 건너뛰고** 남은 사람부터 계속(발송 로그가 근거) |
| 시간대 | 허용 시간대(기본 09:00~18:00) 밖에는 보내지 않는다 |
| 먼저 시험 | 대량 승인 전 **본인 주소 1통 시험 발송**(미리보기·실제 렌더링)이 필수 단계 |

## 2. 안전 설계
1. **승인서 방식(범위 고정)**: 수신자 목록·제목·본문 템플릿·첨부(sha256)로 `scope_hash` 를 만들고 **한 번 승인하면 수정 불가**. 내용을 바꾸려면 새 승인서. 승인은 사람이 화면 버튼으로만(AI 는 승인서를 만들지도 승인하지도 못한다 — 허용 API 목록에 넣지 않고 테스트로 고정).
2. **자동 멈춤 조건**(조용히 계속하지 않는다): ① 연속 실패 3회 ② 로그인 거부·발송 한도·스팸 의심 응답(SMTP 4xx/5xx 중 한도·차단 계열) → **즉시 회차 중단, 승인서를 `paused`로**, 사람 확인 전 재개 안 함 ③ 정지 스위치(전체) ④ 결과 불확실(`unknown`) 수신자는 **재시도 금지**(중복 발송 방지)하고 목록에 "확인 필요"로 표시.
3. **수신거부**: 수신거부 목록(주소 단위)에 있으면 건너뜀. 본문 끝에 수신거부 안내 문구를 넣는 옵션, 회신으로 온 "수신거부" 요청을 사람이 목록에 추가하는 버튼. 홍보·광고 메일이면 승인서에 광고 표기·수신거부 문구 **필수**(정보통신망법) — 성격이 거래 안내인지 광고인지는 승인서 항목으로 기록.
4. **주소 검증**: 형식 오류·중복은 가져오기 단계에서 거부(조용히 빼지 않고 사유 표시). 주소는 로그에서 마스킹, 전체는 DB 에만.
5. **개별화**: 본문·제목에 `{이름}`·`{업체명}` 치환(목록의 열). 치환 값은 본문 정제(`html_sanitize`)를 거친 뒤 넣는다.
6. **첨부**: 기존 규칙(실행 파일 금지, 파일당 20MB, 경로 안전)을 그대로. 수신자 수만큼 반복 첨부되므로 **총 전송량 경고**(첨부 크기×수신자 수)를 승인 화면에 표시.
7. **네이버 한도 불확실성**: 공식 일일 발송 한도를 찾지 못했다. → 기본값을 낮게(200) 시작하고 **실제로 막히는 응답을 만나면 자동 중단·기록**한다. 그 기록으로 상한을 조정(추측으로 올리지 않는다). 천 명 이상을 하루에 보내야 하면 다른 발송 수단 검토가 필요하다(이번 범위 밖).
8. **감사**: 승인자·승인 시각·회차별 보낸/건너뜀/실패/불확실 수, 수신자별 상태(마스킹)를 기록. 비밀번호·본문 원문은 로그에 없음.

## 3. 구성 (레이어·파일) — 하나팩스 대응표
| 계층 | 신규 파일 | 하나팩스 대응 |
|---|---|---|
| L2 정책(순수) | `ai_orchestrator/gates/mail_bulk_policy.py` | `fax_send_policy.py` — 판정·한도·시간대·수신거부·중복·간격 계산·자동 멈춤 판정 |
| L7 저장 | `ai_orchestrator/persistence/mail_bulk_store.py` | `fax_authorization_store.py` — 승인서·수신자 상태·발송 로그·수신거부·정지 스위치(sqlite, `sqlite_schema` 버전 단계) |
| L6 실행기 | `ai_orchestrator/workflows/naver_mail_bulk.py` | `hanafax_auto_send.py` — `run(auth_id, sender, now)`: 한 명씩 보내고 간격 대기, 상한·멈춤 조건 확인, 이어 보내기 |
| L6 서비스 | `ai_orchestrator/services/mail_bulk_service.py` | `hanafax_authorization_service.py` — 가져오기(엑셀·CSV)·승인서 생성/승인/취소·시험 발송·즉시 실행/상태 |
| L6 예약 | `scheduled_job_actions.py` **추가만** | 새 액션 `naver_mail_bulk_send`(파라미터는 승인서 id 하나뿐 — 수신자·내용은 승인서에서 읽음) |
| L8 API | `ai_orchestrator/routers/naver_mail_bulk_router.py` | 승인서 CRUD·승인·취소·시험·실행·로그·수신거부·정지 (관리자 인증) |
| L9 화면 | `admin-web/src/app/mailbox/bulk/*` (메일함 탭 안 "대량 발송") | 하나팩스 탭: 목록 가져오기→내용·간격·상한 설정→본인 시험→승인→진행 상황(보냄/남음/실패/확인 필요)·일시정지·정지 |
| L11 테스트 | `tests/test_mail_bulk_*.py` | 정책(한도·간격·멈춤)·실행기(가짜 발송기로 순차·이어 보내기·불확실 재시도 금지)·저장소·허용 API 고정 |
- 발송 어댑터는 기존 `scripts/naver/mail_imap/sender.py`(`make_draft`/`send_draft`) 를 쓰고 **연결은 한 번 열어 재사용**(건마다 로그인하지 않는다 — 로그인 반복이 차단 사유가 될 수 있음). 필요하면 `sender` 에 "연결 재사용" 함수를 **추가만** 한다.
- `mcp_server.API_REGISTRY` 는 건드리지 않는다(AI 는 대량 발송 승인서를 다루지 못한다).
- 라우트 수 기준값은 추가된 엔드포인트 수만큼 재고정, 모듈 순환 현재값 유지.

## 4. 드라이런으로 확인할 것 (승인 후 코드 전에)
1. `fax_send_policy.evaluate` 의 입력/출력 형태를 메일(주소 기준)로 바꿀 때 달라지는 곳(번호 정규화 → 주소 정규화) 목록화.
2. `sender.send_draft` 가 연결을 매번 여는지 확인하고, 연결 재사용 경로 추가의 영향(풀·TIMEOUT).
3. 가짜 SMTP 로 **200통 순차 실행**: 간격 대기(시간 주입으로 즉시), 상한 도달 후 이어 보내기, 연속 실패 3회 멈춤, 한도 응답 멈춤, `unknown` 재시도 안 함.
4. 게이트 예상: 신규 파일 레지스트리 등록, 라우트 +N, 순환 유지, `SECURITY_PATTERN`(첨부 경로·주소 로그) 0.

## 5. 단계 (직렬)
| 단계 | 내용 | 실제 발송 |
|---|---|---|
| B1 | 정책(순수)+저장소+테스트 | 없음 |
| B2 | 실행기(가짜 발송기)+서비스+예약 액션+API+테스트 | 가짜만 |
| B3 | 화면(가져오기·설정·승인·진행 상황) | 없음 |
| B4 | 본인 주소 시험 발송 → **본인 주소 목록 3건(본인 메일 2개+) 순차 발송 시험** → 앱 실검증 | 본인 주소만 |
| B5 | 실제 목록 운영 투입은 **사용자가 목록·내용·상한을 보고 승인**한 뒤에만 | 사용자 승인 후 |

## 6. 범위 밖 (후속)
- AI 분류 정리(이동·삭제·읽음 처리 제안 카드) — 별도 기준서.
- 반송(bounce) 메일 자동 분석·주소 자동 제외(받은편지함의 반송 알림을 사람이 목록에 추가하는 버튼까지만).
- 클릭·열람 추적, 천 명 이상 단일일 발송용 전용 메일 서비스 연동.

## 7. 결정 대기 (권장안)
1. **하루 상한 기본 200통, 건당 간격 30초(±20%)** — 권장(200통≈100분). 막히는 응답을 만나면 자동 중단·기록.
2. **허용 시간대 09:00~18:00** — 권장.
3. 메일 성격 필드(거래 안내 / 홍보·광고) 필수 입력, 홍보면 광고 표기·수신거부 문구 필수 — 권장.
4. 본인 주소 시험 발송(1통) + 본인 주소 3건 순차 시험을 운영 투입 전 필수 단계로 — 권장.
5. 하나팩스처럼 **다른 곳(엑셀·CSV 주소록)에서 가져오기**를 기본 제공 — 권장.
