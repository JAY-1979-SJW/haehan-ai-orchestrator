# 신규 사이트 온보딩 (처음 보는 사이트 탐색) — 기준서 v1

- 날짜: 2026-09-30 / 상태: **v1 — 드라이런 완료, 사용자 승인 대기** / 브랜치: `feat/login-state-by-element`(후속 브랜치 분리 권장)
- 기존 구현 확인(`capability_check explorer`, 코드 직접 확인): `scripts/explorer/` 의 `auto_explorer`(BFS), `site_crawler`(전체 크롤+미설계 페이지 기록), `page_classifier`, `manual_snapshot`, `page_snapshot`, `page_analysis`, 그리고 로그인 판정 `login_detector`(프로필 `configs/login_probes.json`).
- **원칙: 새 크롤러를 만들지 않는다.** 기존 탐색기를 호출하고 분석 계층을 연결하는 얇은 진입점 1개만 추가한다.

## 1. 목적
처음 보는 사이트의 URL 하나를 주면, 읽기 전용으로 안전하게 둘러보고 **"이 사이트에서 무엇이 어디 있고 무엇이 위험한가"** 보고서와 **로그인 프로필 초안**을 만든다. 이후 자동화 코드는 추측이 아니라 이 보고서를 근거로 짠다(사이트맵 경고 게이트와 연결).

## 2. 드라이런 결과 (2026-09-30, 국가건설기준센터 `kcsc.re.kr`, 읽기 전용·저장 없음, 5.8초)
기존 도구를 코드 수정 없이 그대로 돌려 본 결과 — 무엇이 부족한지가 여기서 확정된다.

| 관찰 | 의미 | 대응 |

## 3. 변경 범위
| 항목 | 내용 |
|---|---|
| 새 파일 | `scripts/explorer/site_onboarding.py` — `onboard(page, url, *, depth, max_pages)` 진입점 + 보고서 조립(순수 함수는 분리해 테스트) |
| 수정 | `page_analysis.classify_page_state` — `login_widget_present` 구분(§2 첫 행). 기존 키·값은 유지, 값 1개 추가 |
| 수정 안 함 | `auto_explorer`, `site_crawler`, `page_classifier` (호출만 한다) |
| 출력 | `data/sitemap/<host>_onboarding_<ts>.json` (기존 저장 위치·규칙 재사용) |
| 레이어 | L4 Browser Engine(범용). 사이트별 지식(L5)은 넣지 않는다. DB·라우터 접근 없음 |

## 4. 안전 규칙 (강제)
- 같은 호스트만, 깊이·페이지 수 상한(기본 depth 2 / 20페이지), 읽기 전용(POST·submit·입력 금지).
- 클릭은 링크/메뉴만. `risk != safe`(발행·결제·삭제·전송·법적 동의) 요소는 **누르지 않고 목록에만** 기록.
- 로그인 화면을 만나면 **입력하지 않는다**. 캡차·2단계 인증·권한 없음 감지 시 즉시 중단하고 이유를 보고.
- 쿠키·세션 값은 읽지 않는다(이름만). 로그아웃 URL 회피(`skip_url_patterns` 유지).
- 새 탭에서만 동작(사용자 탭 불간섭). 끝나면 탭을 닫는다.

## 5. 보고서 내용
사이트 개요(호스트, 방문/예산/미방문 수) · 페이지 목록(URL, 대표 제목, 유형, 상태) · 로그인 후보(로그인 화면 위치, 로그인 버튼·로그아웃·계정 요소와 보임 여부) · 위험 동작 목록(요소·역할·위험 분류·페이지) · 역할 미분류 비율 · 중단 사유(있으면) · **로그인 프로필 초안**(`login_probes.json` 형식, 세션 쿠키 이름은 로그인 전후 비교로 채울 수 있을 때만 후보로 표기).
- 프로필 초안은 **파일에 자동 반영하지 않는다.** 사람이 확인 후 반영.

## 6. 테스트·검증
- 단위: 템플릿 경로 제외, 위험 요소 미클릭, 상태 구분(`login_widget_present` vs `login_required`), 예산 소진 표기, 프로필 초안 형식.
- 변이 시험: 위험 요소 필터 제거, 같은 호스트 검사 제거, 템플릿 경로 필터 제거가 테스트에 잡히는지.
- 실제 화면: 위 드라이런 사이트 + 로그인 필요 사이트 1곳(로그인 화면에서 멈추는지)을 실제 브라우저로 확인. 합성 HTML만으로 통과 보고 금지.

## 7. 위험·한계
- SPA는 링크를 JS로 만들어 BFS가 놓칠 수 있음 → 미방문 링크 수를 보고서에 남기고 완전 탐색을 주장하지 않는다.
- 로그인 뒤 화면은 사용자가 먼저 로그인해야 볼 수 있다(OTP·캡차는 사용자 몫). 온보딩은 로그인 전/후를 각각 실행해 비교하는 방식.
- 역할표는 한국어 업무 버튼 중심이라 해외 사이트는 미분류가 많을 수 있음(§2 두 번째 행).
