## 2. 단계 (직렬, 사이트 연동은 마지막)
| 단계 | 내용 | 사이트 연동 |
|---|---|---|
| **G1 업무판** | 현장·계약 등록 → 해당되는 공무 업무 자동 생성 → 기한·상태 보드 → 서류 체크리스트·첨부 경로 → 기한 알림 | 없음 |
| **G2 공무 AI 업무 창** | 메일함 AI 창과 같은 구조. AI 는 **읽기(현장·기한·서류 현황)와 초안 생성**만, 확정·제출·발송은 사람이 카드 버튼으로 | 없음 |
| **G3 사이트별 연동** | 사용자가 고른 사이트부터 하나씩. **벤더 공식 API 확인 → 있으면 API, 없을 때만 CDP**(프로젝트 규칙). 제출·신고 확정은 항상 사람 승인 | 사용자 선택 시 |
- G3 후보와 사전 조사 메모(착수 시 각각 공식 문서로 재확인): KISCON·공사대장·실적신고(건설산업지식정보시스템), 건설기술인 배치(건설기술인협회·KISCON 연계 여부 확인), 4대보험(4대사회보험 정보연계센터 EDI), 세금계산서(홈택스·민간 연동 서비스 — 약관·인증서 정책 확인), 하이웍스 그룹웨어(앞서 조사한 오픈 API: 전자결재 기안 등, 메일 조회 API 는 문서 미확인). 공동인증서·전자서명·송금·결제는 **자동 실행 금지**(보안 금지선).

## 3. G1 설계 (업무판)
### 3-1. 데이터 모델 (sqlite `storage/gongmu.db`, `sqlite_schema` 버전 단계)
| 테이블 | 주요 필드 |
|---|---|
| `sites`(현장) | id, 이름, 발주처, 공사 위치, 착공일·준공예정일, **우리 회사 지위(원도급/하도급)**, 도급금액, 담당자, 비고 |
| `contracts`(계약) | id, site_id, 상대(협력업체명), 구분(도급/하도급), 계약금액, 계약일, 변경 이력(금액·기간), 첨부 경로 |
| `task_catalog`(업무 기준표) | 코드(L1~P9), 이름, 분류(법정/실무), 설명, 근거 문구, 처리 시점 규칙(이벤트·주기), 적용 조건(예: 금액 기준), 필요 서류 목록, 제출처(시스템 이름), 기본 기한 규칙, 법령 확인 필요 표시 |
| `tasks`(현장별 업무) | id, site_id, contract_id?, catalog_code, 기한, 상태(할 일/진행/제출 대기/완료/해당 없음), 담당자, 메모, 완료 시각 |
| `task_docs`(서류 체크) | task_id, 서류명, 준비 여부, 파일 경로(허용 폴더 안), sha256, 갱신 시각 |
| `events` | 변경 이력(누가 언제 무엇을), 삭제 없음 |
- 기준표 초기값은 §1 표에서 시드. 적용 조건·금액 기준·기한 규칙은 **코드가 아니라 데이터(설정)**.

### 3-2. 자동 생성 규칙(순수 판정 `gates/gongmu_task_policy.py`)
- 현장 등록 시 지위·금액으로 해당 업무를 계산: 예) `원도급 도급금액 ≥ 기준(초기 1억)` 이면 L2 생성, `하도급 계약 금액 ≥ 기준(초기 4천만)` 이면 계약 건마다 L2, 하도급계약이 생기면 원도급자에게 L1, 매년 L3, 착공 시 P1·L4·P8, 월 단위 P4·P6·P9.
- 계약 **변경**이 기록되면 L2 를 다시 생성("변경 시마다"). 기한은 기준일(계약일·착공일)+규칙일수, 모호하면 기한 없이 '기한 확인 필요'로 표시(조용히 추측하지 않는다).
- 이미 있는 업무는 중복 생성하지 않는다(현장·계약·코드·기준일로 판별).

### 3-3. 구성 (레이어·파일)
| 계층 | 파일 | 역할 |
|---|---|---|
| L2 | `ai_orchestrator/gates/gongmu_task_policy.py` | 적용 조건·기한 계산·중복 판정(순수) |
| L7 | `ai_orchestrator/persistence/gongmu_store.py` | 위 테이블 |
| L6 | `ai_orchestrator/services/gongmu_service.py` | 현장·계약 등록, 업무 생성, 상태 변경, 엑셀·CSV 가져오기, 기한 알림 |
| L8 | `ai_orchestrator/routers/gongmu_router.py` | `/api/v1/gongmu/*` (관리자 전용) |
| 예약 | `scheduled_job_actions.py` 에 `gongmu_due_notice`(읽기 전용: 기한 임박·지연 업무를 알림) | 기한 알림 |
| L9 | `admin-web/src/app/gongmu/*` | 현장 목록·업무 보드(기한순·상태별)·현장 상세·서류 체크리스트·가져오기 |
| 테스트 | `tests/test_gongmu_*.py` | 정책(경계값)·저장소·서비스·라우터 |
- 알림 수단은 기존(텔레그램·메일 초안 카드)을 재사용하고 **자동 발송은 하지 않는다**(메일은 승인 카드).

### 3-4. 화면 (`/gongmu`)
현장 선택 → ① **이번 주 해야 할 일**(기한 임박·지연 강조) ② 업무 보드(법정/실무, 상태 열) ③ 업무 상세(근거 문구·필요 서류 체크·첨부·메모·상태 변경) ④ 현장·계약 등록(직접 입력 또는 엑셀·CSV) ⑤ "법령·기준 확인 필요" 표시가 있는 항목은 확인 안내.

## 4. G2 설계 (공무 AI 업무 창, 메일함과 같은 구조)
- AI 허용 API(`mcp_server.API_REGISTRY`, 테스트가 집합 고정): `gongmu.sites`, `gongmu.tasks`(기한·상태 조회), `gongmu.task`(상세·서류 현황), `gongmu.draft`(초안 생성) — **상태 변경·확정·삭제·제출·발송은 허용 목록에 없다**.
- 초안 종류: 기성 청구 내역서 초안, 본사 정기 보고서(공정률·손익 현황) 초안, 하도급 계약 검토 체크리스트, 안전서류 작성 점검표, 서류 누락 요약. 초안은 승인 대기 카드로 저장되고 사람이 "확정"해야 파일/업무 메모에 반영.
- 민감정보: 계약 금액·협력업체 정보는 AI 대화 기록에 남는다(사용자 사전 안내 문구 표시). 자격증명·인증서 정보는 이 기능이 다루지 않는다.

## 5. 범위 밖 / 보안
- G3 사이트 연동 전까지 외부 사이트에 접속·제출하지 않는다. 공동인증서·전자서명·송금·결제 자동 실행 금지.
- 법률·세무 판단 제공 아님(안내 문구). 신고 기한·금액 기준 위반으로 인한 책임을 지지 않으며, 기준값은 사용자가 확인·수정할 수 있어야 한다.
- 파일 경로는 허용 폴더(문서·다운로드 등) 안만, 비밀·앱 내부 파일 거부(메일 첨부와 같은 규칙 재사용).

## 6. 단계별 검증 계획
- G1: 정책 경계값(금액 기준 -1/=/+1, 지위별, 변경 시 재생성, 중복 방지), 저장소(이력 추가만), 서비스(가져오기 잘못된 행 거부), 라우트 인증, 화면 타입체크·ESLint·격리 환경(임시 DB)에서 헤드리스 브라우저로 등록→업무 자동 생성→상태 변경 흐름. 라우트 기준값·모듈 순환·레지스트리 게이트.
- G2: AI 허용 목록 집합 고정 테스트, 초안→카드→확정 흐름, 실제 AI 실행 2회(읽기·초안).

## 7. 결정 대기 (권장안)
1. **G1(업무판)부터 시작, 사이트 연동은 이후 사용자가 사이트를 고를 때** — 권장.
2. 현장·계약 입력은 **직접 입력 + 엑셀·CSV 가져오기** — 권장(현재 진행 중인 현장 목록을 한 번에 넣을 수 있게).
3. 금액 기준(1억·4천만)·기한 규칙은 **설정으로 분리, 초기값은 이미지 문구** — 권장(법령 확인 후 사용자가 수정).
4. 기한 알림은 **앱 화면 배지 + 텔레그램(기존 연동이 있는 경우)**, 메일은 승인 카드로만 — 권장.
5. 첫 시험 데이터: 실제 현장이 있으면 **현장 1곳의 실제 정보**를 사용자가 알려 주고, 없으면 가상 현장 1곳으로 시험(실제 개인정보·계약 정보는 저장소에 올리지 않는다) — 권장.
