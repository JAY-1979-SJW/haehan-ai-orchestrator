# 앱 전체 다크 모드 — 색 추천·구현 주의점 (검토용 초안, 구현 전)

- 날짜: 2026-10-02 / 사용자 요청: "앱 페이지 전체 다크 기능 추가하는데 어떤 색이 좋겠어?" → 추천안을 문서로 저장
- 상태: **색 톤 미확정**, 코드 변경 없음. 톤을 정하면 이 문서를 기준서로 확정하고 구현한다.

## 1. 추천: 슬레이트 네이비 (기본 추천)
지금 앱의 글자색(`#0F172A`)과 브랜드 주황(`#F97316`)이 이미 슬레이트 계열이라 가장 어울린다.

| 용도 | 라이트 (현재) | 다크 (추천) |
|---|---|---|
| 페이지 배경 | `#F5F7FA` | `#0B1220` |
| 카드·사이드바·패널 | `#FFFFFF` | `#111827` |
| 보조 면(툴바, 호버) | `#FAFAFA` / `#F3F4F6` | `#1A2332` |
| 테두리 | `#E5E7EB` | `#2A3547` |
| 기본 글자 | `#0F172A` | `#E5E7EB` |
| 보조 글자 | `#6B7280` | `#9CA3AF` |
| 강조(주황) | `#F97316` | `#FB923C` (어두운 배경에서 대비가 더 좋음) |
| 선택된 항목 배경 | `#FFF7ED` | `#2A1C12` |
| 성공 / 위험 / 경고 | 초록 / `#B91C1C` / 노랑 | `#34D399` / `#F87171` / `#FBBF24` |

- 순수 검정(`#000`)은 피한다: 화면이 너무 번쩍이고 주황 강조가 눈에 거슬린다.

## 2. 다른 선택지
| 톤 | 특징 | 비고 |
|---|---|---|
| 뉴트럴 차콜 (`#18181B` 계열) | 푸른빛 없는 중립 회색 | 주황과 대비가 크고 무난 |
| 웜 다크 (`#1C1917` 계열) | 갈색 기운 | 주황과 가장 따뜻하게 어울리나 일부 화면에서 탁해 보일 수 있음 |

## 3. 구현 시 주의점
1. **색이 코드에 직접 박혀 있다**: 컴포넌트마다 `bg-[#F5F7FA]`, `text-[#0F172A]` 같은 값을 쓴다. 색 변수(CSS 변수 토큰)로 바꾸는 작업이 먼저다. 대상 화면 수에 따라 변경 파일이 많다(착수 전에 전수 집계).
2. **메일 본문(HTML)은 밝은 배경 유지**: 받은 메일은 흰 배경 기준이라 반전하면 글자·이미지가 깨진다(네이버·Gmail 동일). "본문 어둡게" 옵션은 별도로 둘 수 있다. 본문은 격리 iframe 이라 앱 색 변수가 적용되지 않는다 — 의도한 동작.
3. **전환 방식**: 시스템 설정을 따르는 자동 모드 + 상단 토글(라이트/다크/자동), 선택은 이 브라우저에 기억. Electron 앱 창도 같은 페이지를 보여 주므로 함께 적용된다.
4. **서식 편집기·색 선택기**: 편집기 안 글자색 기본값이 검정이므로 다크에서 읽을 수 없는 문제가 생긴다 — 편집 영역은 흰 배경으로 두거나 기본 글자색을 변수로 맞춘다. 보낼 HTML 에는 앱 테마 색이 섞여 들어가면 안 된다(받는 사람은 라이트 기준).
5. **범위가 메일함 탭 밖 전체 화면**: 다른 세션이 건드리는 화면과 겹칠 수 있으므로 착수 전 겹침 확인.
6. **접근성**: 본문 글자 대비 4.5:1 이상 유지. 주황 `#F97316` 위 흰 글자 버튼(대비 약 2.8:1)은 다크·라이트 모두 글자 크기·굵기로 보완하거나 더 어두운 주황(`#C2410C`)을 쓴다.
