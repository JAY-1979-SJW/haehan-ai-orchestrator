## 1. 사전 확인 (프로젝트 규칙)
- `capability_check kiscon` → 기존 구현 없음.
- 벤더 공식 API: 웹 검색(2026-10-03)에서 KISCON 의 공개 OpenAPI·연계 문서를 찾지 못함 → **CDP 가 정당한 경로**(단, "없음"의 확정이 아니라 "못 찾음". 착수 전 kiscon.net 헬프데스크 공지·`cws` 도움말에서 연계 안내가 있는지 한 번 더 본다).
- `configs/vendor_apis.json` 에 KISCON 항목을 `status: no_public_api_found` 로 추가한다(저장소 밖 조사 결과 기록 의무).

## 2. 실측한 사이트 구조 (읽기 전용 탐색)
| 영역 | 주소 | 비고 |
|---|---|---|
| 포털(공개) | `https://www.kiscon.net` | 건설업체 정보조회·벌점·건설업행정정보 등 공개 조회. 로그인 불필요 |
| **건설공사대장 전자통보(CWS)** | `https://cws.kiscon.net/main.aspx` (진입 `domainCheck.aspx`) | 로그인 탭 3종: **건설업체 / 발주자 / 감리자**. ASP.NET WebForms(`__VIEWSTATE` 등), 인증서 필드(`UserSignCert`, `UserDn`) → **공동인증서 로그인** |
| 안내 | 공지·동영상 설명자료(원/하도급 건설공사대장 통보, 헬프데스크) | 전자통보 대상 확인건 문의 게시 |
- 이 앱의 대상은 **건설업체 로그인**(원도급자의 하도급 계약 통보, 공사대장 통보).

## 3. 범위 (직렬)
| 단계 | 내용 | 쓰기 |
|---|---|---|
| **K1 로그인 감지·세션 점검** | 사용자가 CDP 크롬의 `cws.kiscon.net` 에 건설업체 로그인(인증서) → 앱이 **화면 요소로** 로그인 상태 판별(`session_probe` 방식, 읽기 전용) | 없음 |
| **K2 조회** | 로그인 후 통보 대상 공사 목록·통보 상태(미통보/완료/변경 필요)·하도급 계약 현황을 읽어 공무 업무판(L1·L2)과 **대조**만 한다. 화면 구조는 로그인 후 메뉴를 실측해 이 문서에 추가 | 없음 |
| K3 입력 보조 | 업무판의 계약 정보로 통보 화면 폼을 **채우기만** 한다 | 폼 입력만, 제출 안 함 |
| K4 제출 | **자동 제출하지 않는다.** 최종 제출·인증서 서명은 사용자 | 사람만 |
- K1~K2 는 이 기준서 승인으로 진행 가능, K3 는 K2 화면 실측 후 별도 승인.

## 4. 보안·운영
- 공동인증서·비밀번호·세션 쿠키는 읽거나 저장·출력하지 않는다. 로그아웃·쿠키 삭제 금지(로그인 세션 보존 원칙).
- 만료 감지 시 파기하지 않고 사용자에게 재로그인 요청(인증서는 사용자만).
- 연결은 `scripts/web_connector.py` 공유 연결(`run_on_browser_thread`, `get_page_by_url`)만 사용. 새 Playwright 연결 금지.
- 위치(안): L5 `scripts/kiscon/`(세션 점검·조회), 업무판 대조는 L6 `services/gongmu_service` 에서 호출(도메인 간 직접 import 금지 준수 — 어댑터 주입). 테스트는 저장해 둔 HTML 픽스처로(실사이트 접속 없음).
- 법률 판단 아님: 통보 대상 여부·기한은 사이트 표시와 국가법령정보센터 원문이 기준.

### 7-2. 목적·연결
- 공무 업무 **P3(협력업체 관리)**·L1(하도급 통보) 전에 하도급 상대의 **업체상태=정상 / 등록업종 보유 / 하도급참여제한·벌점 여부**를 확인해 업무 서류 체크에 근거로 남긴다.
- 사업자번호는 사이트가 뒷자리를 마스킹해 표시 → 검색 키는 **업체명(+대표자)**, 결과는 사업자번호 앞자리·대표자로 동일성 확인. 동명 다수면 자동 확정하지 않고 후보 목록을 사람에게 보여 준다.
