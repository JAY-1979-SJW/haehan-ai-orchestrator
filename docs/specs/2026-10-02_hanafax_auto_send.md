## 3. 핵심 설계: 발송 승인서 (Fax Authorization)
"미리 승인"은 기존 회차 승인과 다른 개념이므로 **별도 승인서**로 만든다. 승인서가 가리킨 정확한 범위 안에서만 자동 발송한다.

- **승인서**가 고정하는 것(= 승인한 범위): ① 수신자 목록(번호·이름) ② 문서(파일 내용 SHA-256 또는 작성 문서 본문 해시) ③ 제목 ④ 한도(1회 최대 건수·1일 최대 건수·총 건수) ⑤ 유효기간 ⑥ 허용 발송 시간대.
- **범위 해시**: 위 ①~③ 의 정규화 해시. 실행 시점마다 현재 값의 해시를 다시 계산해 **승인 때와 한 글자라도 다르면 발송하지 않고 "재승인 필요" 로 멈춘다**.
- 승인은 사람이 앱에서 수신자 목록·제목·문서 미리보기를 본 뒤 명시적으로 한다. 승인자·승인 시각·범위 해시를 기록한다. 승인서는 **취소(즉시 중단)** 할 수 있다.
- 승인서는 예약 작업·이벤트·화면 예약이 공통으로 참조한다 — 자동 발송은 항상 "유효한 승인서 id" 를 요구한다(없으면 발송 거부).

## 4. 안전장치 (외부 수신자에게 나가는 되돌릴 수 없는 발송)
1. **기본은 드라이런**: 승인서에 `live=false` 가 기본. 드라이런은 수신자 검증·중복 검사·한도 계산·발송 계획까지만 하고 실제 전송은 하지 않는다. 실전송은 승인서에 `live=true` 를 명시적으로 켜야 한다.
2. **중복 발송 방지**: 같은 (수신번호, 문서해시) 는 이미 성공 이력이 있으면 건너뛴다(기존 `hanafax_sent_log` + 새 이력 모두 조회). 사용자가 명시적으로 "재발송" 을 선택한 경우에만 허용.
3. **실패 시 자동 재시도 금지**: 전송 요청이 나간 뒤 결과가 불명확하면(타임아웃 등) **재전송하지 않고 "확인 필요"로 멈춘다**(중복 발송 방지가 재시도보다 우선). 명확한 사전 실패(로그인 실패·번호 형식 오류)만 재시도 대상.
4. **한도**: 1회·1일·총 건수 상한, 초과분은 보내지 않고 남긴다. 한도는 승인서에 고정.
5. **킬 스위치**: 전역 정지 플래그(앱에서 한 번에 모든 자동 발송 중단) + 승인서별 취소. 정지 상태에서는 어떤 경로로도 발송하지 않는다.
6. **잔액 확인**: 발송 전 잔액이 필요한 건수보다 적으면 발송하지 않는다(과금·결제는 사용자 영역 — 충전은 자동화하지 않는다).
7. **허용 시간대**: 승인서의 시간대 밖에서는 발송하지 않는다(심야 발송 방지).
8. **감사 기록**: 모든 판정(발송·건너뜀·거부·사유)과 접수번호를 기록한다. 수신번호는 마스킹해 로그에 남기고 전체 번호는 승인서·이력 DB 에만 둔다. 자격증명·문서 본문은 로그에 남기지 않는다.
9. **수신자 목록 안전성**: 번호 형식 검증, 목록 내 중복 제거, 수신거부 목록(opt-out) 제외(영업공문 대량 발송의 법적·평판 위험 — 수신거부 번호는 영구 제외).
10. **테스트는 실제 발송을 하지 않는다**: 단위·통합 테스트는 가짜 발송기로만. 실전송 검증은 사용자 승인 하에 **본인 번호 1건**으로만(과금 최종 확인은 사용자).

## 6. 네 가지 발송 내용의 연결
- **정기 발송**: 예약 작업의 반복 규칙(recurrence)이 이미 있다 → 승인서 id 를 가진 `hanafax_send` 작업.
- **화면 예약 발송**: 화면에서 수신자·제목·문서를 입력 → 미리보기 → 승인서 생성·승인 → 지정 시각에 예약 작업 실행.
- **영업공문 대량**: 엑셀+배치 JSON 을 승인서의 수신자 목록으로 가져온다(배치 파일 위치는 `HAEHAN_FAX_EXPORT_DIR`/형제 프로젝트 `05. g2b` — 이번에 하드코딩 해소). 건수가 크므로 1회·1일 한도로 나눠 발송.
- **이벤트 발송(입찰·공고 알림)**: **트리거 인터페이스만 만든다**(`이벤트 → 승인서 id + 변수(공고명 등)`). 승인서의 문서가 템플릿이면 변수를 채운 결과를 해시로 승인할 수 없으므로, 이벤트 발송은 **"템플릿 + 허용 변수 목록" 을 승인 범위로** 하고 변수 값은 길이·문자 검증만 한다. 실제 이벤트 원천(나라장터 공고 수집 등)은 **사이트 연결이라 보류** — 사용자가 해당 사이트를 지목할 때 붙인다.

## 8. 위험·대응
- **오발송**: 범위 해시 불일치 시 정지, 드라이런 기본, 승인 전 미리보기, 킬 스위치.
- **중복 발송**: 성공 이력 조회 + 불명확 결과는 재시도 금지.
- **사이트 변경으로 자동화 깨짐**: 하나팩스는 공개 API 가 없어 화면 의존. 발송 직전 사전 점검(로그인·잔액)을 하고, 결과를 확정 못 하면 "확인 필요" 로 멈춘다.
- **다른 세션과의 충돌**: `scheduled_job_actions.py`·`router.py`·`nav.ts` 는 메일 세션이 수정하는 파일 — 착수 전 겹침 확인, 커밋은 파일 지정.

### 9.3 구현 계획
1. **즉시 발송**: 승인서(사전 승인)로 자동 발송하는 P1·P2 완료. 남은 것 — 실제 발송기 어댑터(`send_fax` 호출, `definite_failure` 구분), 승인서 API, 승인 화면.
2. **예약 발송**: 두 가지 방법 중 선택 필요 — (a) 앱 예약 작업 프레임워크의 시각에 발송(앱이 켜져 있어야 함, 이미 구현됨), (b) 하나팩스 사이트의 자체 예약 기능(`pop_ReserveSel.asp`)에 예약 등록(앱이 꺼져도 발송됨, 사이트 화면 실사 필요). (a) 로 먼저 하고 (b) 는 실사 후 판단.
3. **그룹 발송**: 하나팩스 주소록(`address_List.asp`)을 앱의 수신자 그룹으로 가져오거나 앱 자체 그룹을 승인서의 수신자 목록으로 쓴다 — 주소록 화면 실사 필요.
4. **실사(읽기 전용)**: 하나팩스에 로그인된 브라우저가 필요하다. **로그인은 사용자만 가능**(프로젝트 규칙). CDP 브라우저를 켜고 사용자가 한 번 로그인하면 이후 화면 탐색은 AI 가 읽기 전용으로 수행한다.

## 10. 화면·AI 창 연동 (P4, 2026-10-02 사용자 지시)
지시: "앱에 하나팩스 탭을 별도 페이지로 만들고 AI 창과 연동, 첨부 파일 경로를 알려주면 알아서 첨부해 발송하되 **발송 전 승인 요청은 필수**", "**발송 전 미리보기 목차는 보여 주되 볼지 말지는 사용자 몫**".
- **탭**: `/hanafax`(nav 항목 "하나팩스"). 왼쪽 = 요청 목록·상세·승인·지금 발송·이력·전체 정지, 오른쪽 = AI 창(`UniversalChat`). 승인 대기 건은 4초마다 새로 고쳐 AI 창에서 올린 요청이 바로 보인다.
- **AI 연동**: AI 에이전트(MCP `call_api` 허용목록)는 `hanafax.draft`(승인 대기 초안 생성 — 전송 없음)·`hanafax.authorizations`(조회)만 쓸 수 있다. 첨부 파일 경로·수신자·제목을 받아 초안을 만들고 "하나팩스 탭에서 승인하세요"라고 안내한다. **승인·발송·정지·수신거부·취소는 허용목록에 없다**(테스트가 고정).
- **승인 필수**: 서버가 승인 전 `run` 을 거부(`not approved`). 승인은 화면의 "이 내용으로 승인" 버튼(`confirmed=true`)으로만. 승인 시 문서 내용이 요청 때와 같은지 재확인하고, 발송 직전에도 해시를 다시 비교한다.
- **미리보기 = 선택 사항**: 상세의 "미리보기 보기(선택)" 를 펼치면 ① 제목 ② 첨부 파일 경로 ③ 수신자 목록 ④ 한도 ⑤ 발송 시간대 목차가 보인다. 펼치지 않아도 승인·발송할 수 있다(보기를 강제하지 않는다 — 승인 행위 자체는 필수).
- **기본 드라이런**: "실제로 전송" 을 체크해야 실전송 승인이 된다.
- **남은 위험**: 로컬은 `AUTH_ENABLED=False` 일 수 있어 API 인증이 약하다. AI 가 승인 API 를 직접 부르는 것은 MCP 허용목록과 `--allowedTools`(MCP 도구만)로 막고 있으나, 별도 셸 도구가 열린 세션이면 이론상 가능 — 승인 버튼에 사람 확인 토큰(예: 일회용 코드)을 두는 강화는 P5 전에 검토.
- 다음: P5 본인 번호 1건 실전송(사용자 승인·과금 확인), 예약 발송 화면 연결.

## 11. AI 창 승인 카드·주소록 대량·단체발송 (P4b, 2026-10-02 사용자 지시)
- **사용자 흐름**: AI 창에 문서 경로 + 전화번호(또는 주소록 엑셀/CSV 경로)를 준다 → AI 가 `hanafax.draft` 로 승인 대기 초안을 만들고 답변 끝에 `[[fax-approve:<id>]]` 를 적는다 → **AI 창 안에 승인 카드(버튼)가 나타난다** → 사용자가 "승인하고 발송"을 누르면 끝까지 자동 발송. 승인은 사람이 버튼으로만 하고, AI 는 승인·발송 API 를 쓸 수 없다(허용목록 테스트 고정). 미리보기는 카드 안 접이식(선택).
- **주소록 가져오기**: `recipients_file`(xlsx/csv). '팩스' 열(없으면 '연락처'·'전화')과 '업체명' 열을 자동 인식. 잘못된 번호·중복·수신거부·**예전 발송 이력(`data/hanafax_sent_log.json`)에서 이미 성공한 번호**는 빼고 건수를 `import_summary` 로 알린다. 한도는 비우면 수신자 수만큼(상한 1000).
- **단체발송**: 수신자가 2명 이상이면 하나팩스 단체발송(`send_fax_bulk`, 로그인·업로드 1회)으로 50곳씩 묶어 보낸다. 묶음마다 정지·취소를 다시 확인하고, 묶음 결과가 불명확하면 남은 묶음을 보내지 않고 멈춘다(재전송 금지). 1명이면 기존 단건 경로.
- **테스트 안전**: 가짜 발송기가 단건·단체발송 두 엔진 경로를 모두 막는다(실제 사이트에 닿지 않는다).
