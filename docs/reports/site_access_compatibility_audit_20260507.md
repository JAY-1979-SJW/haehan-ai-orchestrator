### 1. Google 계열 (4개 사이트)

|--------|-----------|---------|
| Google 로그인 | OAUTH_API_ONLY | OAuth consent (사용자 직접) |

## 주요 발견 사항

### 1. 공동인증서 의존도 높음
- 은행, 정부, 세무, 보험 등 대부분 공동인증서 기반
- 보안프로그램 설치 필수로 서버 브라우저 자동화 불가능
- 로컬 PC의 사용자 직접 조작만 가능

### 2. 원격접속 차단 정책
- 은행, 세무 등 민감한 금융 사이트에서 원격접속 차단
- VPN/IP 우회 불가능
- 로컬 PC 필수

### 3. Google 서비스 API 통일
- Gmail, Drive, Calendar 모두 OAuth + API 지원
- 브라우저 자동화 완전 불가능
- API connector 경로로만 가능

### 4. 공개 데이터 기반 사이트 (G2B)
- 공개 공고는 비회원 접근 가능
- API 지원으로 자동화 가능
- 입찰 등 민감한 기능은 불가능

## 결론

**현 단계 결론:**

1. **Google 서비스**: OAuth/API 필수, 브라우저 자동화 불가능
2. **금융 사이트**: 로컬 PC + 사용자 직접 조작만 가능
3. **공공 사이트**: 로컬 agent + 공동인증서, 제한적 자동화
4. **공개 데이터**: API 활용으로 자동화 가능
5. **내부 시스템**: 사용자 승인 필수

**권장 전략:**

- **Tier 1**: API 기반 접근 (Google, G2B) → 서버 자동화 가능
- **Tier 2**: 로컬 Agent + 사용자 직접 입력 (은행, 세무, 보험) → 제한적 자동화
- **Tier 3**: 사용자 직접 조작 (내부 시스템) → 자동화 불가능
