## 2. 목표 아키텍처

```
[공개 다운로드]  웹사이트/릴리스 → 설치 파일 (서명된 exe)
      ↓ 설치 (불특정 다수)
[Electron 씬 클라이언트]
   ├─ 로그인/가입 화면 → 원격 서버
   ├─ 메인 UI ← 원격 서버가 사용자별 제공
   └─ local-agent → 사용자 PC에서 브라우저 자동화 (본인 로그인 세션)
        ↓ device_token WS (사용자 계정에 묶임)
[서버 haehan-ai.kr] — 멀티테넌트
   ├─ 인증: 가입→승인→로그인  ✅ 완료
   ├─ 사용자별 데이터 격리 (모든 데이터에 user_id)   ← 핵심 미완
   ├─ 사용자별 에이전트/세션
   └─ 사용자별 UI 제공
```

## 3. 현재 상태 (실측)

| 구성 | 상태 |
|------|------|
| 회원 인증(가입·승인·로그인) | ✅ 완료, 운영 반영됨 |
| 배포 데몬/파이프라인 | ✅ 복구됨 |
| signup/login 공개 | ✅ nginx 예외 적용 |
| **업무 데이터 사용자별 격리** | ❌ **없음** (단일 테넌트 — 모두 공유) |

| **배포용 경량 클라이언트** | ❌ 현재 풀 번들만 (~1GB) |

→ 인증 골격은 섰으나, "각자 자기 것" 멀티테넌트와 배포 클라이언트가 미완.

## 3-B. ✅ 확정 결정 (2026-06-02): 순수 로컬 per-user 설정

데이터 격리 방식을 **"서버 멀티테넌트"가 아니라 "각 사용자 로컬"** 로 확정.

- 서버는 사용자 **업무 데이터를 보관하지 않음.** 인증 + 사이트 카탈로그 + 통제만.
- 각 사용자 PC에 자기 사이트 선택·설정·자격증명·세션·데이터 전부 로컬 저장.
- "서버 통제"의 핵심 레버 = **가입→승인 게이트(이미 완료)**. "누가 쓸 수 있나"로 통제.
- 데이터 원본은 항상 로컬 → 추후 "설정 목록만 서버 동기화(v2)"를 얹기만 하면 되므로 막다른 길 아님.

**→ 기존 P1(서버 멀티테넌트 데이터 격리)은 폐기.** 대신 "사이트 선택 + 로컬 저장 + 카탈로그"라는 훨씬 작은 작업으로 대체.

비유: VS Code 본체(서버) + 확장 마켓(카탈로그) + 내가 고른 확장·내 파일(로컬).

```
서버 = 인증(승인) + 사이트 카탈로그 + 통제
  PC = 사이트 선택 + 설정·자격증명·세션·데이터 (전부 로컬)
```
